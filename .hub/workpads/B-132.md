# B-132 — Let the live SDP bundle check survive a slow fetch

## Change

`tests/testthat/test-schema-helpers.R` now runs the live remote loader through
a test-only wrapper that passes a 30-second per-request timeout to the existing
fetcher. It skips only when the captured fetch error is an httr2 transport
failure without an HTTP response. A missing upstream path (HTTP 404), bundle
parse error, or validation error still fails. The existing positive assertions
still require a remote bundle with matching profile identifiers and a version.

The wrapper leaves the package fetcher's two-second default and public runtime
behaviour untouched. There is no Python behaviour to mirror and no NEWS entry:
only a test's handling of an unavailable network changes.

## Verification

- RED: the new deterministic transport regression failed on the first focused
  run because the loader converted the timeout into a CLI error; the test
  expected a skip. The same regression constructs an HTTP 404 response and
  expects an error, so the skip cannot conceal a broken upstream ref or path.
- GREEN: `NOT_CRAN=true Rscript -e 'pkgload::load_all(".", quiet = TRUE);
  testthat::test_file("tests/testthat/test-schema-helpers.R", reporter =
  "summary", stop_on_failure = TRUE)'` passed locally with both network tests
  enabled. A test fetch also checks that the wrapper passes timeout 30 and
  retains `source = "remote"`.
- `git diff --check` passed. CI remains the check for its own network conditions.

## Boundary

The transport skip retires if the live test uses a guaranteed local upstream
fixture. Until then it avoids treating a failed network fetch as evidence that
the upstream schema is invalid. B-132 makes no queue, package runtime, or
ontology term change.
