## What changed, and where

**`scripts/build-pkgdown.R`**

- **One list of contributor-only sources.** `internal_sources` names
  `AGENTS.md`, `CLAUDE.md`, `HUB.md` and `.github/PULL_REQUEST_TEMPLATE.md`.
  The pages deleted after the build (each `.html`, and the `.md` companion
  pkgdown writes for llms.txt) and the forbidden-text patterns are derived from
  it. So the two new files are excluded exactly as AGENTS.md and CLAUDE.md
  already were: deleted after the build, left out of the rebuilt search index
  and sitemap, and the run fails if any generated file still names one. For
  AGENTS.md and CLAUDE.md the derived paths and patterns are the ones the
  script hard-coded before.
- **A classification guard, new.** Before building, every file that pkgdown's
  own `package_mds()` would render as a page must be in `internal_sources` or
  in `public_sources`, which is empty. A file in neither stops the run and
  nothing is built. The list decayed because a Markdown file could be added at
  the root without anyone deciding whether it was public; this makes that
  decision happen the first time the site is built with the file.
- **A toolchain guard, new.** Before building, the script compares the running
  pkgdown version, its GitHub SHA and pandoc's version with `docs/pkgdown.yml`,
  the checked-in site's own record. It reads the running values with the same
  three expressions pkgdown's `site_meta()` uses to write that record. On any
  difference it stops, names each one, and builds nothing.
  `--accept-toolchain-change` builds anyway and prints the differences first.
  An unknown argument stops the run with the usage line, so a mistyped flag
  cannot pass silently.
- **Why pkgdown needs this.** In pkgdown 2.2.1, `package_mds()` returns every
  Markdown file at the root and under `.github/`, less README, NEWS and
  LICENSE, less a skip list compared case-sensitively against
  `pull_request_template.md`. So `.github/PULL_REQUEST_TEMPLATE.md` is
  rendered, and nothing in pkgdown skips `HUB.md`. Read from the installed
  source, not assumed.

**`.gitignore`**: `docs/HUB.html` and `docs/PULL_REQUEST_TEMPLATE.html`,
beside the existing `docs/AGENTS.html` and `docs/CLAUDE.html`. They cover a
build run without the script.

**Nothing under `docs/`.** No hub page is tracked there: `git ls-files docs` at

## Found along the way, not this item

- **Candidate: `.gitignore` covers only the `.html` page of each
  contributor-only source.** pkgdown also writes a `.md` companion of every
  page for llms.txt. In 2.2.1 `build_llm_docs()` does this, and the harness
  above measured it. So a build run without this script leaves `docs/AGENTS.md`,
  `docs/CLAUDE.md`, `docs/HUB.md` and `docs/PULL_REQUEST_TEMPLATE.md` untracked
  and not ignored, each carrying the full text of its source. The script
  deletes all four. The safety net for a run without the script does not cover
  them. The gap affects all four sources alike and predates this item, so it is
  named here rather than absorbed.

## Guards added, and what retires them

- **The classification guard (`internal_sources` and `public_sources`) and the
  post-build exclusion.** Retire when pkgdown can be told not to render a given
  root Markdown file, or none of these files lives where pkgdown looks for them.
- **The toolchain guard and `--accept-toolchain-change`.** Retire when `docs/`
  stops being committed from a local build, for example because CI builds and
  deploys the site from a pinned toolchain. Its stated limit: the record holds
  only pkgdown's version, its GitHub SHA and pandoc's version. bslib, downlit
  and R can also rewrite every page, and nothing checks them.
