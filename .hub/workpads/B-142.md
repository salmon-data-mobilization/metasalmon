### Why this is more than a session option: the yaml 2.2.x default

#111's test comment and NEWS text, and B-189's card, describe the exposure
as a session that turned `yaml.eval.expr` on. That understates it. yaml's own NEWS:
2.1.19 *"Added `eval.expr` option"*, 2.3.0 *"Made `eval.expr` default to
`FALSE`"*. From CRAN's archive (sha256 of each tarball):

| yaml | `yaml.load()` signature | tarball sha256 |
|---|---|---|
| 2.2.0 | `eval.expr = getOption("yaml.eval.expr", TRUE)` | `55bcac87eca360ab5904914fcff473a6981a1f5e6d2215d2634344d0ac30c546` |
| 2.2.2 | `eval.expr = getOption("yaml.eval.expr", TRUE)` | `a5dc6aba2719eb4422bdd7d3a7b2223bbb00e4470fa234d8c5b3a6835d99f730` |
| 2.3.4 | `eval.expr = getOption("yaml.eval.expr", FALSE)` | `cb2625ada9996ebadd24930dae89fff6523366f82d07757e8b0ed260a0ff72a6` |

In 2.2.0's `src/r_parse.c:319-341` the tag is parsed and evaluated in
`R_GlobalEnv` when `eval_expr` is true. The deprecation warning fires only
**after** evaluation. DESCRIPTION's floor is `yaml (>= 2.2.0)`.

Measured, not just read: I built yaml 2.2.2 from the archive into a scratch
library and loaded the package on it, **with no option set**:

```
main   yaml 2.2.2, option yaml.eval.expr set: FALSE
  .ms_closure_mapping_paths()        evaluated: TRUE
  .ms_fetch_remote_sdp_schema()      evaluated: TRUE
fixed  yaml 2.2.2, option yaml.eval.expr set: FALSE
  .ms_closure_mapping_paths()        evaluated: FALSE
  .ms_fetch_remote_sdp_schema()      evaluated: FALSE
```

So on an install DESCRIPTION permits, the remote rules read on `main` runs R
code from a document fetched over the network, with no user action. The fix
covers the whole declared range: `read_yaml()` and `yaml.load_file()` forward
`...` to `yaml.load()` in 2.2.0 as well. **The floor stays at 2.2.0**, because
raising it would not have removed the option case anyway.

## Guards added, and what retires them

- **`tests/testthat/test-yaml-expr-guard.R`**. *Retires when* yaml stops
  evaluating `!expr` altogether, or metasalmon stops parsing YAML. It does
  **not** retire when DESCRIPTION's floor reaches 2.3.0, because the option
  still turns evaluation on there, and that is the case its behavioural tests set.
  Two maintained lists, each carrying its own maintenance rule in the file:
  `yaml_reader_fns` (add a parser when `R/` starts calling one) and
  `known_yaml_read_fns` (the reach check: delete an entry when its read is
  deleted). Both scans are held to that reach check. The stated limits are
  now a reader reached through a computed string and a parser missing from
  `yaml_reader_fns`. The source scan closed the third limit, which was
  top-level code run at build time.
- **The source scan's own skip.** When the R/ sources cannot be found it
  fails on CI and skips elsewhere, with a reason that starts "NOT CHECKED".
  *Retires when:* nothing; it is how the layer reports that it could not look.
- **One skip:** `skip_if_not_installed("emld")` on the `write_eml_from_sdp()`
  test. That function aborts before its read when emld is absent, so without
  emld the test could only pass vacuously. This matches every other
  `write_eml_from_sdp()` test. *Retires when* emld becomes a hard dependency,
  or the read moves ahead of the emld check.
- **One rebinding:** the vendored-rules test rebinds `yaml::read_yaml` inside
  the yaml namespace for that test only (`local_mocked_bindings(.package =
  "yaml")`). The rebinding forwards the caller's own arguments, so it changes
  only which file is opened. *Retires when* `.ms_load_vendored_sdp_schema()`
  takes its rules path from somewhere a test can point elsewhere.
