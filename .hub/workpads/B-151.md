## What changed and where

### `R/review-console.R`

- **`.ms_review_is_code_slot()`** (new, round 1): whether a slot is a code's
  slot, meaning its write-back address includes `code_value`. It is read from
  `.ms_review_target_keys()`, so "a code's slot" has one definition.
- **`.ms_review_match_slot_rows()`**: `code_value` now has three states rather
  than two. `NULL` leaves it unconstrained, as before. A value selects that
  code's slot, as before. **A blank value (`""`, or `NA`) now selects the slots
  that belong to no code**, which are the column's own slot and a table's.
  Before, a blank value went through
  `!is.na(review$code_value) & review$code_value == ""`, which excluded every
  no-code row, so `code_value = ""` aborted with *"No review slot matches"*.
  Whether a slot belongs to a code is read from its file, not from an empty
  `code_value`; see *Codex review, round 1*. The function now normalises its own
  argument with `.ms_scalar_text()`, so the NA-safety its comment claims holds
  even if a caller does not do that first.
- **`.ms_review_call_args()`**: when `(column, role, table)` still matches more
  than one slot, a slot that belongs to no code now gets `code_value = ""`. The
  old rule added `code_value` only when the row had one, which is the
  escalation gap the item names. A code's slot gets its code value as before.
  It gets nothing when that value is empty, because `""` would now decide the
  column's own slot instead.
- **`.ms_review_resolve_slot()`, the ambiguity refusal**: a slot that belongs
  to no code and shares its table with code slots is now offered as
  `table = "t", code_value = ""`. The old option was bare `table = "t"`, the
  argument the call already carried, so following the message could not reach
  the column's own slot. A slot in a table with no code slots among the matches
  is still offered as bare `table = `, so the two-table case prints what it
  did.
- **roxygen for `code_value`**, and `man/accept_suggestion.Rd` regenerated:
  says what `""` and `NA` select, that an omitted value matches the codes'
  slots too, and that a blank never selects a code's slot.

**What did not change, on purpose: an omitted `code_value` is still
unconstrained.** The item offers two fixes, and the other is to read the
omission as "no code value". That fix would change what an already-printed
call resolves to. A code slot's call is printed without `code_value` whenever
`(column, role)` is unique at print time. That is the case for a column with a
single code, when the column has no slot of that role in the queue: a
categorical column never has one, and a measurement column's own slot leaves
the queue once filled. With that fix, the same pasted line would resolve to the
column's own slot if one is queued, and to nothing if not. The pasted call is
the audit trail, so this fix leaves the meaning of every earlier-printed call
alone. Earlier versions never printed `code_value = ""`, and the calls they did
print resolve exactly as they did.

**The printed spelling is `""`, not `NA`.** `code_value = NA` is accepted and
means the same thing. The printed form is `""` because it is the one literal
both implementations can print alike. Python's `None` is already the
unconstrained default, so a Python spelling of "absent" has to be `""`. If R
printed `NA`, the two consoles would print different calls, and that
difference would need a parity-register row.

### `tests/testthat/test-review-console.R`: three helpers, two fixtures, six tests

- **`expect_printed_calls_decide_their_own_slots()`** (helper) runs every
  printed accept and reject line and checks it decides **the slot and rank it
  was printed under**. That is stricter than the file's existing load-bearing
  test, which checks that one decision was recorded and that its IRI is the
  candidate's. A call that resolves to a sibling slot passes that check and
  writes the wrong field. Each call is also checked to be a rendered line, so
  the text run is the text a user pastes. Since round 1 it takes `must_run`,
  which defaults to every slot. A slot left out of it may refuse as ambiguous,
  but no call may ever decide a slot other than its own.
- **`measurement_code_review()`** (fixture) builds the collision the way
  discovery builds it. A measurement column has its own `entity_iri` and
  `constraint_iri` slots. Two codes each have one `codes.csv` slot, carrying
  constraint, entity and method candidates.
- *"a measurement column with a code list prints a call that reaches its own
  slot"*: the column's call carries `code_value = ""`, and every printed call
  decides its own slot.
- *"a blank code_value selects the column's own slot, and an omitted one still
  matches every code"*: `""` and `NA` both select the column's slot, and the
  bare call still refuses. This pins the design choice above.
- *"doing what the ambiguity refusal says reaches every slot it matched"*: each
  option the refusal lists is added to the call and run, and together they
  must reach every slot the bare call matched. This reads the options from the
  condition's `body`, not from formatted text, so it does not depend on the
  bullet glyph or the locale.
- *"a measurement column with a code list round-trips from create_sdp() to
  disk"*: the real pipeline. It runs `create_sdp(semantic_code_scope = "all")`
  with a two-code sentinel list (`-9` *Not surveyed*, `-99` *Survey
  abandoned*) on a count column, with `find_terms` mocked. It checks the
  collision is real for `entity` and `constraint`, and that every printed call
  decides its own slot. Then it pastes the column's entity call and runs
  `apply_sdp_semantics()`. The chosen IRI must land in
  `column_dictionary.csv` `entity_iri`, and `codes.csv` must be unchanged.
  Since round 1 the package build and the paste-and-apply check are the helpers
  `measurement_code_package()` and `expect_column_call_writes_the_dictionary()`.
- Round 1, **`vocabulary_code_review()`** (fixture) with *"a blank code_value
  never selects a code slot whose codes.csv row has no code value"*: the
  column's own slots must run, `""` and `NA` must select the column's entity
  slot, and the refusal must offer the column's slot an option that reaches it.
- Round 1, *"a measurement column whose codes.csv row names a vocabulary
  round-trips from create_sdp() to disk"*: the Codex finding through the real
  pipeline, with the same paste-and-apply check.
