# B-152: The network guards in test-github-helpers.R probe a host and a credential path the code under test never uses

Queue item: `queue/items/B-152.yaml` (defect, metasalmon). Its `retires_when` is
the condition this branch meets and is not restated here.
Evidence pointer: `knowledge/backlog.md`, the `B-152` entry.
Branch: `agent/B-152/a-14cac14e9127d2f7`, from `main` at `87bba38`.

## What changed and where

One file, `tests/testthat/test-github-helpers.R`. No package code changed.

- **A probe that makes the fetch the code under test makes.**
  `skip_unless_raw_github_serves(url, token)` sends a GET to the raw URL,
  carrying the token as `Authorization: token <token>`. That is the host and the
  header `ms_github_get()` uses (`R/github-helpers.R`). It skips when the request
  cannot complete or is answered with a status of 400 or above. It builds the
  request itself instead of calling the package, so a defect in the package
  still fails the test rather than becoming a skip. It retries transient
  statuses as `ms_github_get()` does, and has a 30 s timeout so a stalled host
  skips instead of hanging.
- **`read_github_csv can read remote content with a token`**: its two `gh::gh()`
  probes of `api.github.com` are replaced by that probe of the exact URL the
  test fetches. `read_github_csv()` never touches the API, so those probes
  covered nothing it does.
- **`read_github_csv_dir can fetch when a token is configured`**: its `gh::gh()`
  probes stay, because the listing half goes through `gh::gh()` with the same
  token (`ms_github_list_contents()`). The raw probe is added after them, for
  the first listed CSV, which covers the per-file fetches. It probes one file
  and not every file, so a fetch that fails for one particular file still errors
  instead of becoming a skip.
- **Two offline pins**, using httr2 mocked responses, so they run on CI where
  the network always works:
  - *the raw-host guard sends the request read_github_csv() sends* captures
    both requests and requires the same URL and the same `Authorization`
    value. It also requires that the code did send the token, so the identity
    check cannot pass vacuously.
  - *the raw-host guard skips when that host refuses the request or cannot be
    reached* checks three cases: 404 skips, a transport failure skips, and
    200 does not skip.

  Each pin skips on an httr2 too old for the API it uses: 1.2.0 for
  `req_get_headers()`, 1.0.0 for `local_mocked_responses()`.
  `test-llm-chat-request.R` does the same, because DESCRIPTION pins no httr2
  version.

**No `NEWS.md` entry.** `AGENTS.md` asks for one on an observable behaviour
change. This change is test-only, and nothing a package user can observe moves.

### Which list this falls in

**This is a delegated defect fix, not a guard narrowing.** On CI, the probe
makes the same request, with the same token, that the test's own fetch already
completes there. So both tests still run and pass there, as the CI reading
above shows. Here is how each skip condition changed:

- **The first test** skipped when the API refused the token or was down. It now
  skips when the raw fetch it performs would fail.
  - Where the API is down and the raw host works, it now runs where it used to
    skip.
  - Where the raw host fails, it now skips where it used to error.
- **The directory test** keeps every skip condition it had. It gains one, which
  fires only when its first per-file fetch would fail, which is where it used
  to error.

So the only behaviour that changed is an ERROR becoming the SKIP the guard was
meant to give. CI coverage of both tests is unchanged.

## Retirement conditions of the guards added

Both are stated in the test file.

- **The raw-host probe** retires when these tests stop reaching the network. If
  `ms_github_get()` changes the host it fetches or how it sends the token, the
  probe changes in the same commit, and pin 1 fails until it does.
- **The pins' httr2 version skips** retire when DESCRIPTION's Imports requires
  httr2 (>= 1.2.0).
