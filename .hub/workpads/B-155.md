# B-155 — Verify and retry the CI pak bootstrap

## Changes

`scripts/install-ci-pak.R` makes three bounded attempts to install the stable
pak binary in the runner's dedicated library. Success requires loading its
namespace: `install.packages()` returning after a warning-only download failure
does not count. Exhaustion fails Rscript with an infrastructure message naming
the bootstrap and stating that package tests and R CMD check have not run.

The workflow delegates its pak bootstrap to this script and supplies the
documented `pak-version: none` input to `setup-r-dependencies@v2`. The upstream
action retains dependency resolution, installation and caching. Its sibling
checkout, parity guard, isolated-provider suite and strict R CMD check remain
ordinary failure-producing steps. No package behavior or ontology choice
changes, so there is no Python package capability to port.

The bootstrap's retirement condition is in its header: remove it when the
upstream action both retries failed pak downloads and verifies pak loading.
The [official action source](https://github.com/r-lib/actions/blob/v2/setup-r-dependencies/action.yaml)
documents the external library/skip input and currently performs an unchecked
`install.packages()` invocation in its Unix bootstrap.

## Verification

Files were frozen before running the focused test. On local R 4.5.2,
`Rscript scripts/tests/test_install_ci_pak.R` passes six offline proofs:
SSL failure followed by success, warning-only permanent download failure,
infrastructure classification, an unloadable namespace, first-attempt success,
and exit status 1 from an exhausted child Rscript. No network or library
installation occurs in this test. The workflow YAML parses with R's existing
`yaml` package; `git diff --check` passes.
Both R files parse. Invoking the actual bootstrap with an unset installer
library exits 1 with the expected infrastructure message, without a download.

The first YAML validation probe found that the shell Python has no PyYAML;
the existing R parser was used without adding an environment dependency.
Live Ubuntu/current-R verification belongs to the PR check. A full package
suite is unnecessary locally because neither R package code nor package-test
commands changed; CI still runs both the full suite and strict package check.
