## What changed and where

One file: `tests/testthat/test-semantic-closure.R`. A fixture, a search
stand-in and one test, placed directly after the test that pins the other
direction ("the two canonical sets differ and the producer derives both").

- **`make_closure_procedure_sdp()`**, the fixture. `make_eml_test_sdp()` plus
  one categorical column, `estimate_method`, bound to the `count` measure as
  `http://www.w3.org/ns/sosa/usedProcedure` in an observation structure, with
  two `codes.csv` rows whose `term_iri` values are
  `https://example.org/methods/mark-recapture` and
  `https://example.org/methods/expanded-count`. Both are canonical measurement
  IRIs and neither is a canonical review target.
- **`closure_procedure_search_index()` and `closure_procedure_stub()`.** The
  stub wraps the file's existing `closure_search_stub()`, answers the two
  procedures under role `method` and under no other role, and records the query
  and role of every call.
- **The test**, "a code-resolved procedure is a vocabulary term and never a
  review target". No evidence row names a procedure, so their vocabulary rows
  can only come from the search, which is what puts
  `.ms_closure_iri_roles()`'s fallback on the path. It asserts:
  1. the closure run raises no warning (no gap, no incomplete row, no
     placeholder);
  2. both directions of the set difference in one package: the procedures are
     measurement-only, and `smn:Observation` is review-only;
  3. read back from disk, both procedure IRIs are in
     `metadata/semantic_vocabulary.csv` (6 rows) and neither is in
     `reviewed_semantic_selections.csv` (5 rows);
  4. every search for a procedure was made under role `method`;
  5. both gates, `.ms_eml_read_vocabulary()` and
     `.ms_eml_read_semantic_review()`, accept the pair, so a ledger with no
     procedure row is complete rather than short.

No `R/` code, `NEWS.md` entry, parity register or metasalmonpy file changed.
This change adds a test and changes no behaviour, and nothing is owed to the
parity register.

**No ontology term was chosen.** The procedure IRIs are `example.org`
placeholders, as in `helper-observation-structures.R`. The two SOSA IRIs
(`sosa:usedProcedure` as the component relation, `sosa:Procedure` as the stub's
`type_iris`) are the ones the existing fixtures already use in the same roles:
`component_test_rows()` and `add_table_method_to_review_closure()`.

### What B-192's head start gave, and what it could not

B-192's scratch reproduction, described in `.hub/workpads/B-192.md`, built the

## Found, not absorbed

- **Candidate, the metasalmonpy half of B-171.** Pin the same direction in
  `tests/test_semantic_closure.py`, with a mutation of `_iri_roles()`'s
  fallback shown to fail it. The mirror is behavioural, and no behaviour
  differs, so this is a test gap there and not a parity row.
- **Candidate, the producer's gap and incomplete rows for a code-resolved
  procedure name a slot that does not exist.** `.ms_closure_target_context()`
  (`R/semantic-closure.R:478-524`) handles an IRI with no review target by
  defaulting to scope `code`, file `codes.csv` and field `method_iri`, and
  leaves `table_id`, `column_name`, `code_value` and `target_row_key` empty.
  `codes.csv` has no `method_iri` column: the IRI is in its `term_iri`, on a row
  whose table, column and code value are all known. Measured on the unmutated
  producer, with this fixture and the plain `closure_search_stub()`, which does
  not know the procedures, so both become gaps:

  ```
                                unresolved_iri target_scope target_sdp_file
  1 https://example.org/methods/expanded-count         code       codes.csv
  2 https://example.org/methods/mark-recapture         code       codes.csv
    target_sdp_field table_id column_name code_value target_row_key
  1       method_iri                            <NA>
  2       method_iri                            <NA>

  placement_rationale[1]:
  The package asserts this IRI in method_iri and searching smn/gcdfo for it returned nothing, ...

  codes.csv columns: dataset_id, table_id, column_name, code_value, code_label, code_description, vocabulary_iri, term_iri, term_type
  ```

  The warning a user sees says `method_iri = https://example.org/methods/...`.
  The only SDP metadata schema with a `method_iri` column is `tables.csv`'s
  (`inst/extdata/schema/frictionless/metadata/tables.schema.json`), and the IRI
  is not there. A gap row is what `render_ontology_term_request()` builds a
  term request from. metasalmonpy makes the same choice at
  `semantic_closure.py:608`. The row is reached whenever a code value's
  `term_iri` is a procedure that smn and gcdfo lack. It is not in B-171's
  retirement condition, and the brief puts any producer defect in an item of
  its own.
