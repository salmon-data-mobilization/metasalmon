## What I changed and where

1. **`R/sdp-field-setters.R`**
   - **`.ms_is_unresolved_iri()`**, new: the second predicate the card asks
     for. A vectorised wrapper over the existing `.ms_is_review_iri()`
     (`R/package-helpers.R`), which matches the marker with the same pattern
     both strict-validation sweeps use (`^\s*REVIEW\s*:`, case-insensitive).
     `.ms_is_review_placeholder()` and `.ms_is_unfilled_metadata()` are
     **unchanged** and stay narrow; the comment records why, and why
     `.ms_review_is_unfilled()` is not a substitute (it is blind to the prose
     spellings — the trade the card warns about).
   - **`.ms_review_iri_files()`**, new: the files in which the scan reports a
     marker — `tables.csv` and `column_dictionary.csv`, which are exactly the
     files `validate_salmon_datapackage(require_iris = TRUE)` refuses one in. The
     comment names B-177 (`codes.csv`, `dataset.csv`), the one difference from
     metasalmonpy, B-185, and its retirement condition.
   - **`.ms_metadata_iri_hint()`**, new: one spelling of the IRI prompt. The two
     existing IRI branches now read it; their strings are byte-identical to
     before.
   - **`.ms_metadata_gaps_for_file()`**: a marker branch in the main field loop,
     straight after the prose-placeholder check. A schema-declared `*_iri` field
     of a swept file carrying the marker is reported with reason `iri`, **on any
     row** — the dictionary validator sweeps every row, not only measurement
     rows. The `observation_unit_iri` and measurement branches keep the prose
     test, so a marker is reported once, not once per branch.
   - Roxygen for `review_metadata()`: the "What it reports" list gains the marker
     bullet, including that `codes.csv` / `dataset.csv` markers are not listed
     and why. File header updated to name the marker among the rules.
2. **`man/review_metadata.Rd`**: regenerated with roxygen2 8.1.0. The
   `Config/roxygen2/version: 8.0.0 -> 8.1.0` bump it wrote into `DESCRIPTION`
   was reverted as unrelated tooling churn; the Rd diff is the one bullet.
3. **`tests/testthat/test-sdp-field-setters.R`**: three helpers
   (`filled_coded_package()`, `mark_metadata_field()`,
   `refuses_review_marker()`) and five tests:
   - **the validator-driven table**, which is the pin the retirement condition
     asks for. On a package with codes, filled by executing `review_metadata()`'s
     own printed calls (the fixture asserts that it then passes strict
     validation), it marks each
     schema-declared `*_iri` field of all four metadata files in turn and asserts
     that the scan reports it **exactly when** strict validation refuses it.
     Expectations are written out, not read from `.ms_review_iri_files()` (the
     lesson metasalmonpy's test records), and coverage is read from the schema,
     so a newly declared `*_iri` field fails the test until somebody writes down
     what strict validation does with it. `refuses_review_marker()` treats a
     refusal for any other reason as an error, so a fixture that broke for an
     unrelated reason cannot pass as a refused marker. The dictionary marker goes
     on a `categorical` row on purpose: only the marker test can find it there.
   - **the item as measured**: one marker on `constraint_iri`, red before; after,
     the one printed call is executed and strict validation passes.
   - **once, not twice**: all four measurement IRIs plus `observation_unit_iri`
     marked; five rows, and the printed calls run (a doubled row would name an
     argument twice and could not).
   - **the predicates**: the new one answers the marker and nothing else; the
     prose ones stay blind to it.
   - **B-185's residual, pinned**: an undeclared `custom_thing_iri` column in
     `tables.csv` carrying a marker is still missed while the validator refuses
     it. Mirrors metasalmonpy's `test_an_undeclared_iri_column_is_still_missed`.
4. **`NEWS.md`**: development version, `### Fixed`.

No validator was touched. `validate_dictionary()` and
`.ms_collect_review_iri_issues()` are byte-identical; which files strict
validation sweeps is B-177's question.
