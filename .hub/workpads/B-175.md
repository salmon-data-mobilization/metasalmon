### Why this shape

1. **Fix the shared accessor, not the call sites.** `.ms_metadata_schema_fields()`
   is the one read the scan, the setters and the validator's blank-required
   collector share, so reading the bundle there removes the fetch from all of
   them.
2. **A separate cache slot, not `.ms_load_sdp_schema(source = "vendored")`.**
   The loader's cache is one slot keyed by source, so a vendored read through it
   evicts the session's `auto` bundle. The next writer, reader or validator
   call then fetches all eight documents again. A script could also stamp two
   packages with different profile identities, which is the exact property the
   loader's comment says it caches the fallback to protect. metasalmonpy reads
   its bundled documents outside its loader cache for the same stated reason.
   Test 2 pins this, and RED demonstration 2 shows that the naive fix fails it
   while passing the network test.
3. **The validator's blank-required collector follows, deliberately.**
   `.ms_collect_blank_required_metadata_fields()` (`R/package-helpers.R`)
   reaches the accessor through `.ms_schema_required_metadata_fields()`, and its
   own comment claims *"read from the same schema parse [`review_metadata()`
   reads], so the two cannot disagree about which fields block"*. Moving only
   the scan would have made that comment false. metasalmonpy made the same
   choice explicitly (`package_io.py`, `source=_SCHEMA_SOURCE`). **No result
   changes today**: measured below, the bundled and published copies of all six
   metadata schemas are identical.
4. **No warning when `metasalmon.sdp_schema_source` would be ignored.** These
   five functions now read the bundle whatever that option says. The option is
   documented to no user: it appears in no Rd file and no vignette, only in
   `R/schema-helpers.R` and one NEWS paragraph. The port has no warning either
   (`_SCHEMA_SOURCE` is unconditional), so adding one would open a deviation.
   The behaviour is documented in the roxygen instead of warned about.

- **I did not change `.ms_load_sdp_schema()`'s default source.** Making it

  alter every writer, which is a design change and not this item.
- **I did not add a warning for an ignored `metasalmon.sdp_schema_source`.**
  See "Why this shape", point 4.
- **I did not rebuild the pkgdown site.** `docs/reference/review_metadata.{html,md}`
  and `set_sdp_dataset.{html,md}` keep the old wording. Their one claim,
  *"never contacts a network"*, becomes true with this change, and only the

  anyway.** `pkgdown::build_reference()` aborts with *"In _pkgdown.yml, 1 topic
  missing from index: "write_sdp_semantic_closure""* (see the candidates
  below), and B-116's page for that function was never generated either.
- **I did not correct the backlog's "up to 16 seconds when it hangs".** It is
  refined here instead, because B-174 and B-176 are editing the same backlog
  section in parallel. A host that never answers costs **one** timeout,
  measured at 2.1–2.5 s per cold call, because the first failed request aborts
  the whole bundle fetch (`purrr::map`), and the loader then falls back. The
  16 s figure (8 × 2 s) bounds only a host that answers each request just
  inside the timeout.

## Mirror

**metasalmonpy owes nothing behavioural for this item.** This is the R half of
the change metasalmonpy pull request **#28** already made (B-126: `ead77a3`,
guard strengthened in `00935d7`). Scan, setters and the validator's
blank-required check all read the bundled copy, outside the loader's cache.
**No parity-register row is owed**, as the card says: this is a shared defect
fixed on both sides, not a chosen difference. The implementation differences
are internal and have no observable behaviour:

- R reads the validated bundle, cached in its own slot. Python reads the raw
  bundled documents through an `lru_cache`.
- R hard-wires the bundled read in `.ms_metadata_schema_fields()`. Python
  threads a `source=` argument through four accessors.
- R's second guard is a proxy listener. Python's patches the socket API. Both
  are client-independent, and R's scope limit is written in its test header.
- R's setter documentation states the no-network property. Python's setter
  docstrings do not; its module docstring and `review_metadata()` docstring do.

No metasalmonpy queue item exists or is needed for this. The one Python-side
candidate is the missing `set_sdp_code()` assertion above.

## Guards added, and what retires each

- **`.ms_vendored_sdp_schema()` and the bundled read in
  `.ms_metadata_schema_fields()`.** *Retires when* `.ms_load_sdp_schema()` no
  longer fetches on its default source. At that point every caller can read the
  default, and both carry no meaning. The retirement condition is written at
  both sites.
- **`tests/testthat/test-review-metadata-offline.R`.** *Retires when* never,
  while `review_metadata()` documents that it does not contact a network. The
  file header says so, and states what the proxy layer cannot see.
- **The un-pinning of `metasalmon.sdp_schema_source` inside that file.** This
  is not a suppression: it undoes the suite-wide `vendored` pin in
  `helper-validation.R` for the length of each test, and restores the option
  and every schema cache slot afterwards.
