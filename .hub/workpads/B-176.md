## What changed and where

### `R/metadata-write.R`

- **`.ms_review_slot_address_cols()`** (new): the nine columns that say which
  metadata cell a suggestion row is about — `dataset_id`, `table_id`,
  `column_name`, `code_value`, `dictionary_role`, `target_scope`,
  `target_sdp_file`, `target_sdp_field`, `target_row_key`. The same nine, in the
  same order, as metasalmonpy's `_SLOT_ADDRESS_COLUMNS`.
- **`.ms_review_hand_picked_source()`** (new): `"user"`, metasalmonpy's
  `_HAND_PICKED_SOURCE`.
- **`.ms_review_with_hand_picked_accept()`** (new): builds the row — address
  columns copied from the head of the slot, every other column set to a typed
  missing value, `iri` the accepted IRI, `source` `"user"` when the file has a
  `source` column, `decision` `accepted` — and binds it in **before the first
  row of the slot**, so the retrieved candidates keep their relative order.
- **`apply_sdp_semantics()`, the decision-record loop**, three changes:
  - the slot mask is **recomputed per decision** rather than once before the
    loop, because an insertion shifts every later position;
  - the accepted-row test uses **`%in%` instead of `==`**. The loop now branches
    on `any(accepted)`, and `==` against a row with no IRI yields `NA`, so
    `any()` of a mask holding an `NA` and no `TRUE` is `NA` and the `if` stops
    with *missing value where TRUE/FALSE needed*. The old code never called
    `any()` and silently skipped `NA` positions in the assignment, so `%in%`
    reproduces its result exactly for every row it already handled;
  - when **no row of the slot carries the accepted IRI**, the new row is
    inserted; otherwise the matching row is marked `accepted` exactly as before.

Nothing else moved: the dictionary and descriptor writes, `review_semantics()`,
`.ms_review_recorded_decisions()` and every exported signature are untouched.
The file's **column set is unchanged**; a slot decided by a hand-picked IRI
gains one row. No roxygen text changed, because metasalmonpy's fix changed no
docstring either and the two `apply_sdp_semantics()` docs read the same today.

## Found, not absorbed — four candidates, none with an existing item

Searched `queue/items/` for each; the nearest, **B-117** (strict validation and
the EML exporter disagreeing about `term_type`), is a different question.

1. **`detect_semantic_term_gaps()` reports a false ontology gap for a recorded
   hand-picked accept — introduced here in R, already live in metasalmonpy since
   #28.** The recorded row has a blank `search_query`, so the gap detector's key
   (`.ms_semantic_assessment_join_cols()`) puts it in a target of its own whose
   only candidate has `source` `user`, which is not `smn`. Measured with
   `detect_semantic_term_gaps(suggestions = semantic_suggestions(path))` after
   one hand-picked accept: **1 gap row before, 2 after, in both
   implementations**; the new row is `spawner_count · variable`,
   `top_non_smn_iri` = the hand-picked IRI, `top_non_smn_source` = `user`. A
   hand-picked `smn` IRI would be reported the same way, as a non-`smn` gap,
   because classification is by `source`. **Exposure is limited:** no function
   in either package feeds the post-review record to the detector (R's
   `read_salmon_datapackage()` attaches no suggestions; Python's read dictionary
   carried none in this fixture either), and the post-review vignette
   deliberately re-runs `suggest_semantics()` instead. But a gap row is a claim
   that the term-request pipeline acts on. **What a fix has to decide is a
   semantic question, so it is probably Brett's:** whether a recorded
   hand-picked accept is excluded from gap evidence as non-retrieval, counted as
   a reviewer's signal with its own `gap_detection_basis`, or carries its
   target's `search_query` so it groups with the real target (the last diverges
   from #28 and misattributes the query in `write_sdp_semantic_closure()`).
   **Recommendation: exclude recorded decisions from gap evidence**, since a gap
   row asserts retrieval absence and this row is not retrieval output.
2. **A replayed accept ranked past `max_candidates` is invisible to
   `review_semantics(include_filled = TRUE)`** — pre-existing, shared, unchanged
   here. On a six-candidate slot, `accept_suggestion(..., rank = 6)` after
   `review_semantics(max_candidates = Inf)`, applied, then rebuilt at the
   default: **0 decided rows shown and no `DECIDED` line, in both**. The slot
   still leaves the default queue, because `decided` is computed before the
   rank filter; only the view hides it. Head insertion is why a hand-picked
   accept does not hit this, and it is the same failure one step over.
3. **`accept_suggestion(iri = "REVIEW:")` accepts an IRI that is empty once the
   marker is stripped** — shared, and **made more visible by this change in R,
   exactly as #28 did in Python.** The non-empty check runs before
   `.ms_strip_review_iri()`. On `main`, apply clears the field and records
   nothing; here and in metasalmonpy it clears the field and records an
   `accepted` row with an empty `iri`. The row is inert: `review_semantics()`
   drops it, `apply_semantic_suggestions()` drops it, and the closure reader
   drops it. Fix at the source, in both: validate the stripped value. Not done
   here because it changes `accept_suggestion()`'s argument validation, which
   is outside this item, and because doing it only in R would open a parity
   difference.
4. **A hand-picked IRI that equals a lower-ranked candidate's gets `term_type`
   `skos_concept`, while `rank = k` on the same candidate gets the candidate's
   own type** — pre-existing, shared, unchanged here. `apply_sdp_semantics()`
   asks whether the decision was recorded on the row carrying the accepted IRI,
   and `accept_suggestion(iri = )` always records on the slot's first row.
   Measured with an `owl_class` candidate at rank 2: `iri = <that IRI>` writes
   `skos_concept`, and re-applying the rebuilt review writes `owl_class`. So
   that one path is not byte-stable across the rebuild, in both implementations.
   It does not affect the case this item fixes, where no candidate carries the
   IRI and both writes are `skos_concept`; the `NEWS.md` sentence about
   byte-identical re-application is scoped to that case for this reason.
