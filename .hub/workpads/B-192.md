# Workpad — B-192

## Queue item

**B-192**: the publication vignette describes the semantic review-target set as
the measurement set plus observation units, which makes a reader break their
own package.

The item file, `queue/items/B-192.yaml`, is the only home of its state and its
retirement condition, and this workpad restates neither. Its evidence is the
`B-192` entry in `knowledge/backlog.md`.

## What changed and where

- **`vignettes/post-review-package-publication.Rmd`, step 10.** The sentence
  calling the canonical review target set "that same set *plus* each table's
  `observation_unit_iri`" is replaced. The set is now described on its own
  terms: one target for each filled slot among the six semantic fields on
  `measurement` dictionary rows and each table's `observation_unit_iri` and
  `method_iri`. Both directions are stated: an `observation_unit_iri` is a
  review target and not a vocabulary term, and a `sosa:usedProcedure` reached
  through a code value is a vocabulary term and not a review target. It says
  what the ledger gate does to a ledger row added
  for a code-resolved procedure: refuses it as unexpected, in
  `write_eml_from_sdp()` and `publish_sdp_to_knb()`, while
  `validate_salmon_datapackage(require_iris = TRUE)` still passes.
- **`NEWS.md`**, under *metasalmon (development version)*, `### Fixed`. A
  reader could have followed the old sentence, and the reproduction below shows
  what it cost them, so the correction is user-visible.

No R code, test, guard, skip or validator changed. No ontology term was chosen:
the example IRIs below exist only in a scratch script.

### Where the R text follows metasalmonpy #31 and where it does not

metasalmonpy pull request 31 corrected `guides/semantic-review.qmd`, whose
prose was transcribed from this vignette. That passage is unchanged on
metasalmonpy `main` at `70fa8fd`. The R text follows its structure and claims,
with R names, and departs from its wording in three places, each because the
Python wording is not accurate for R:

1. **"the package stops validating"** becomes the two calls that refuse the
   ledger, plus the fact that strict validation goes on passing. Step 10 of
   this vignette opens by saying strict validation is not the publication
   gate, and `validate_salmon_datapackage()` never reads the ledger: only
   `write_eml_from_sdp()` calls `.ms_eml_read_semantic_review()`, and
   `publish_sdp_to_knb()` reaches it through `write_eml_from_sdp()`. Measured
   below.
2. **"no reviewer ever selected it as a slot"** becomes "the ledger has no
   slot for it". In R a reviewer can choose a code value's `term_iri`:
   `suggest_semantics(codes = )` generates suggestions for missing
   `codes.csv$term_iri` targets, and `apply_sdp_semantics()` writes
   `codes.csv`. What the code supports is narrower: the review-target builder
   reads only the six semantic fields of `measurement` dictionary rows and two
   `tables.csv` fields.
3. **"It is every slot a reviewer decided:"** becomes "It has one target for
   each filled slot among these:". The list after the colon is exactly what the
   builder reads, and a reviewer decides other slots too, so the list and not
   the reviewer defines the set.

The item's own gloss, that the procedure "comes from the data rather than from
a metadata field", is kept in substance and named in R terms: the procedure is
reached through the code values in the data, not through any field the review
target set reads. `.ms_eml_used_procedures()` keeps only code values observed
alongside a populated measure.

The review-target table is reflowed to one line per row here; the values are
the script's. The added row used `target_sdp_field = term_iri` and
`dictionary_role = method`; any key fails the same way, because no canonical
target carries a procedure IRI. `publish_sdp_to_knb()` was called with
`public = TRUE`: without it the dry run stops at its own argument check before
reaching the ledger.

What the run shows beyond the item: a hand-added row meets the digest check
first, re-pinning the digest moves the refusal to the exact-set check, and
re-running `write_sdp_semantic_closure()` removes the row, because the writer
builds the ledger from the canonical targets and reads decisions from
`semantic_suggestions.csv`, never from an existing ledger.
