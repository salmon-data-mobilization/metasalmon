## Queue item

**B-197 — A DataONE outage reds every check run that executes while it lasts,
whatever the diff, because one test makes a live call it does not need** (P2,
stream S15, repo `metasalmon`). Claimed 2026-09-16T18:44Z by
`a-d592f9a0947ebb37`. Evidence: `knowledge/backlog.md`, section *The 2026-09-16
network-guard finding*.

Retirement condition, in two clauses: **(1)** the test at
`tests/testthat/test-knb-publication.R:1124` makes no network call at all,
demonstrated by running it with network access removed and seeing it **pass**
rather than skip; and **(2)** the sweep — every other test in that file that
reaches a network service is made offline the same way, or, where the service
is genuinely the thing under test, guarded with skip-on-outage. Clause 2 is
part of the condition because fixing the one instance that fired is not a fix
for the class.

## What changed, and where

One hunk, in `tests/testthat/test-knb-publication.R`. `dataone::CNode("PROD")`
is replaced by `methods::new("CNode")` with an `@identifier` set locally, which
is how the test already builds `member_node` two lines above. A comment records
why the node is built rather than fetched, so the next reader does not restore
the call.

**The call was removable because it was not load-bearing, and that was checked
rather than assumed.** `.ms_knb_lookup_pid_default()`
(`R/knb-publication.R:3291-3320`) passes `client@cn` straight into
`.ms_knb_lookup_node_system_metadata()`, which this test mocks; the mock reads
`node@identifier` and nothing else. So `@identifier` is the only slot anything
touches, and the assertion compares against `coordinating_node@identifier`
rather than a repeated string literal — which means the literal is a fixture
and the test pins what it always pinned: that the lookup visits the client's
`mn` and then its `cn`, in that order.

No exported signature, no return-value attribute, no ontology term IRI, and no
frozen column was touched. No `NEWS.md` entry: the change is confined to
`tests/`, and no observable package behaviour moves.

## Commands run, and what they showed

The network was removed by pointing every proxy variable at a dead local port,
and **the block was proved before any green run was trusted** — a probe of
`https://cn.dataone.org/cn` reports `Couldn't connect to server`.

**RED, the line this item removes** — `dataone::CNode("PROD")` under that
block: `ERROR: Couldn't connect to server [cn.dataone.org]`. **GREEN, the
replacement** under the identical block: built offline, `identifier =
urn:node:CN`.

**Clause 1 and clause 2 together, in one run.** `test-knb-publication.R` with
the network blocked: **zero failures**, and exactly one skip — *expanded KNB
plan bytes are independent of the process locale*, for want of a contrasting
collation locale, which is not a network skip. That is the same single skip the
online run produces. So the target test **passes** rather than skips (clause 1),
and no other test in the file reaches a service (clause 2). The file is clean.

**Independently, the real instance was re-diagnosed from CI rather than taken

`tests/testthat/test-schema-helpers.R`,** although the run below shows both are
defective in this item's own family. They belong to `B-152` and `B-132`, both
`icebox`, and HUB.md's rule is that a finding belonging to another item is named

removal, not a skip, because a skip throws away the assertion it guards.

## Findings that belong to other items

- **`B-132` is confirmed, and is invisible under the default local run.**
  `test-schema-helpers.R:172` *the live upstream SDP bundle loads* errors with
  the network down: `Unable to load remote SDP Frictionless schema bundle`.
  It only appears when `NOT_CRAN=true` — without it, `skip_if_offline()`
  short-circuits through `skip_on_cran()` and the test reports as *On CRAN*, so
  a plain `Rscript` run on a developer's machine sees a skip where CI sees an
  error. That is worth carrying into B-132's fix: its guard's failure mode is
  hidden from exactly the run a developer would use to check it.
- **`B-152` has two more instances, and the file's real shape is better than
  the card's: four tests, three different wrong guards, and not one of them
  is a missing guard.** The card names `test-github-helpers.R:146` and `:234`,
  whose guards probe `api.github.com` while the code fetches
  `raw.githubusercontent.com`. The two it does not name:
  **(a)** *read_github_csv without token can read a known public GitHub raw CSV*
  (`:168`) is guarded by `skip_if_offline()` at `:169` and still **errors** at
  `:171` under the block. That is B-132's claim reproduced in a second file and
  it is worth stating precisely: a dead proxy leaves DNS working, so
  `skip_if_offline()` resolves the host, concludes it is online, and hands the
  test to a fetch that cannot complete. The guard is not absent and not
  misdirected — it asks a question whose answer does not predict the one that
  matters.
  **(b)** *read_github_csv_dir handles empty directories* (`:276`) is guarded at
  `:278` by `skip_if(!nzchar(token), ...)` and fails at `:288`, where an
  `expect_error(..., "not found|404")` gets a connection error instead. That
  guard proves a **token is configured**, which says nothing about whether
  anything is reachable.
  So the family is one defect with three faces — guarding the wrong host, the
  wrong layer of the request, and the wrong precondition entirely — which is a
  stronger case for fixing them in one pass than the card currently makes.
  *(Recorded as a correction: this paragraph first said `:288` had no guard at
  all and that `:171` was guarded by `skip_on_cran()`. Both were wrong, and
  wrong in the direction that would have made the fix easier than it is — a
  missing guard is added, a guard that asks the wrong question has to be
  re-designed.)*
- **`B-137` is confirmed exactly as written, and this container is the
  environment it describes.** `Sys.getlocale("LC_CTYPE")` is `C` and
  `l10n_info()$\`UTF-8\`` is `FALSE` here, and the suite produces its six
  failures: `test-dictionary-helpers.R:224`, the four Unicode-whitespace cases
  at `test-iri-predicates.R:39/52/57/104`, and `test-review-console.R:231`.
  None carries a skip guard. They are unrelated to the network and to this
  change, and they are the reason a bare local suite run on this machine is not
  a baseline for anything.
- **A re-run erases the evidence of the flake it fixes, from every default
  view.** Across 484 `R-CMD-check` runs the API reports 10 that ever finished
  failed and **none since 2026-09-01** — yet four runs carry `run_attempt > 1`,
  three of them in the last five days (runs 337, 360 and 449, on 2026-09-12,
  -09-15 and -09-16). A re-run overwrites the run's conclusion, and
  `get_job_logs(failed_only)` reads the latest attempt, so it answers *no failed
  jobs* for a run whose first attempt died. Attempt 1's log is reachable only by
  following the API's redirect to blob storage **with the Authorization header
  stripped**, or it 401s. This is not any one of B-132/B-152/B-155/B-197 — it is
  the reason all four were cheap to miss, and it has no queue item. Proposed to
  Brett 2026-09-16 rather than filed unilaterally.
