# Workpad — B-200

## Queue item

**B-200**: no check that a `NEWS.md` entry under a released heading was in the
tree the tag names.

The item file, `queue/items/B-200.yaml`, is the only home of its state and its
retirement condition (`retires_when`), and this workpad restates neither. Its
evidence is the `B-200` entry in `knowledge/backlog.md`. Its pair is `B-201`,
the metasalmonpy half.

## What changed and where

- **`scripts/check-changelog-window.py`**, new, beside
  `check-parity-registers.py`. Standard library only. For every released
  heading in `NEWS.md` it finds the version's bump commit, diffs the section
  as it stood there against the section now, and asks `git blame` which
  commit added each added line and `git merge-base --is-ancestor` whether
  that commit is an ancestor of the bump. Its docstring states the exemption,
  what it does not cover, its exit codes (0, 1, and 2 when it cannot run —
  including a shallow clone), and its retirement condition. A `metasalmonpy`
  profile (`CHANGELOG.md`, `## Unreleased`, `pyproject.toml`, reached through
  `METASALMONPY_PATH`) exists so that B-201 can reuse the script.
- **`scripts/tests/test_check_changelog_window.py`**, new: 23 tests, each
  building a throwaway repository and running the script as a subprocess. The
  RED demonstration the item names is `TestTheWindow` and `TestTheExemption`.
- **`.github/workflows/changelog-window.yaml`**, new: on every pull request and
  on pushes to `main`, no path filter, a full-history checkout, the tests, then
  the check. No existing workflow changed.
- **`AGENTS.md`**, *Releases*: the closing sentence that pointed at this item
  now names the script as the pre-tag step, where to run it, and the two
  marked forms a correction must take.

No `NEWS.md` entry: nothing in the package changed (`scripts/`, `.github/`
and `.hub/` are all in `.Rbuildignore`), and `check-parity-registers.py`
landed without one either.

## One deviation from the written condition, and why

**The first-commit fallback, read literally for every untagged version, is red
on `main`.** The item measured only `v0.4.0`. Measured here over every released
heading at `origin/main` `372ef07`: 49 lines under two untagged headings were
added by commits that are not ancestors of the first commit whose `DESCRIPTION`
reads the version.

- **0.2.4**: bump `e739f91` (#15); lines from `041d5dd` (reached `main` in #16,
  `fbda99b`) and `8930467` ("docs: add the 0.2.4 NEWS entries…", #17,
  `fa94968`), both merged while `DESCRIPTION` still read 0.2.4.
- **0.1.6**: bump `f774673` (#5); lines from `e00bba9`, `b546417` and `0e6a142`,
  all merged in #7 (`5dfe5c9`) while `DESCRIPTION` still read 0.1.6.

Neither version was ever tagged, and `AGENTS.md` says the 0.2.x ones are
deliberately untagged history, not to be backfilled. Before the rule existed,
entries accumulated under a version's heading while it stood.

**Resolution:** tags and the open window are exactly as the item specifies. An
untagged version that a later version has superseded is measured as it stood at
the *last* first-parent commit whose `DESCRIPTION` read it. What it gained while
it stood passes. A line added after it was superseded is still a finding, so no
historical heading goes unchecked against new additions. While a version is
current, the first commit rules, so CI sees such a line when it is written. The
docstring states this, what it forgives, and what would retire it.

**Alternatives considered:** leaving superseded untagged headings unchecked
(simpler, but a line added today under 0.2.3 would pass), or an allowlist of the
five commits (literal elsewhere, but it hard-codes history, and a later typo fix
to one of those lines would turn red).

**A hand-built fixture:** bump to 0.1.0, then a bullet under it. Exit 1, "1 line

development heading gives exit 0, "no findings".

**Three design choices, each shown RED against its alternative** (scratch
copies of the script with one line changed, run against this test file):

- The literal first-commit fallback everywhere:
  `test_an_untagged_version_superseded_is_measured_where_it_stood` fails, and
  `main` gives exit 1 with 49 lines.
- Pairing a replaced run by difflib's `ratio` instead of characters kept:
  `test_the_edited_line_stands_for_its_original_even_beside_a_short_one` fails.
  The ratio scores `NEWS.md`'s own closing line `"  how widely it already
  held.)*"` above the edited line at 1664 (0.554 against 0.541), and so reports
  the edited line as the one added.
- No tag requirement for the versions AGENTS.md says are tagged:
  `test_a_superseded_release_the_policy_tags_needs_its_tag` fails. The hazard
  was measured on a `--no-tags` clone of `main` at `372ef07`. There, 0.4.0 read
  as untagged history, was measured where it last stood, and passed even with
  `--no-exemption` (exit 0). With the rule, that clone exits 2: "no tag for
  v0.4.0, v0.3.0 in this clone, though every release from 0.3.0 forward is
  tagged".

**`git blame` and a configured ignore list:** with `blame.ignoreRevsFile` naming
`0909953`, plain blame attributed none of its nine `NEWS.md` lines to it.
`--ignore-revs-file=` restores all nine, and the script passes it.

`python3 scripts/hub_queue.py lint` and `check`: OK. `git diff --check`: clean.
