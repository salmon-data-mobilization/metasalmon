# B-209 — Reject a narrow grammar of duplicated queue facts

## Rule before implementation

The discrimination rule was written in `queue/README.md` before code or CI
changes. It recognizes complete paragraph/list-start assertions of a known
queue item's state, claimability or blockers. Optional code/bold decoration and
unordered/ordered lists do not change ownership. Matching prose is rejected
even when it agrees today; links and existing generated item blocks are the
supported current-state surfaces.

The grammar ends at punctuation or the end of the assertion. Past tense,
conditionals, leading attribution and trailing snapshot/old-card attribution
are outside it. This is not a general language/history detector: paragraph
internal facts and alternative wording remain review subjects. The check reads
the existing four prose roots plus NEWS and retained Theme A evidence. Both CI
path filters include the additional roots. Item YAML remains the primary record.

Generated blocks retain their separate freshness check. Fenced examples state
syntax, not current state. This check retires when downstream prose no longer
owns queue facts or a structured successor makes this syntax guard unnecessary.
No per-file exception, claim rule, approval step or package behavior changes.
No ontology term choice or Python behavior port is involved.
