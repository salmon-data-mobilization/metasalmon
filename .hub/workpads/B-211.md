## What changed and where

- `R/sdp-field-setters.R`, `.ms_metadata_gaps_for_file()`. `add()` now keeps
  one gap row per field of each metadata row. A `reported` vector is reset at
  the top of each row; `add()` returns without adding a row for a field
  already in it. The field loop runs first, so a placeholder keeps the loop's
  `placeholder` row and a `REVIEW:` marker keeps the loop's `iri` row (B-174's
  branch). A blank field the loop passes over is still reported by the
  `observation_unit_iri` or measurement-IRI branch, as `iri`, as before. The
  branches' predicate is unchanged (`.ms_is_unfilled_metadata()`). The comment
  on the `observation_unit_iri` branch said the prose test was what kept a
  field from being reported twice. That was wrong for a prose placeholder, so
  it was rewritten.
- **This is the rule metasalmonpy shipped for B-212, applied the same way**:
  the first check to report a field keeps it, and the field loop runs first.
  R's structure takes it without change. `add()` already received the row, and
  the scan already walks one metadata row at a time, so the only new state is
  the per-row `reported` vector. The two packages now report the same rows for
  every case measured here.
- `tests/testthat/test-sdp-field-setters.R`: `unfilled_iri_states`,
  `fill_iri_templates()`, the three state tests, and `a field two checks both
  find is reported once: a required IRI a configured schema declares`. Each
  state test plants its value in `tables.csv` `observation_unit_iri` and in the
  measurement row's `unit_iri`, on a package that otherwise passes strict
  validation (`filled_coded_package()`). It asserts one row per field with the
  expected reason, **evaluates every printed call**, then asserts that nothing
  is left and that strict validation passes. `fill_iri_templates()` fills every
  `*_iri` template with an IRI, because a placeholder's hint is its own text and
  `fill_templates()` would have filled it with prose.
- `NEWS.md`: an entry at the end of *metasalmon (development version)*,
  `### Fixed`.

  shared owes no row.

## Found, not absorbed

- **Candidate, no item yet: two metadata rows with one address print one call
  that repeats arguments, in R as in metasalmonpy.** `.ms_metadata_render_lines()`
  groups gap rows by file, `table_id`, `column_name` and `code_value`. So a
  `column_dictionary.csv` carrying the `spawner_count` row twice gives one
  `set_sdp_column()` call that names each of that row's fields twice. Measured
  on `83e5d2a` with a scratch script: `formal argument "column_description"
  matched by multiple actual arguments`. B-212's workpad measured the same in
  metasalmonpy (`keyword argument repeated: column_description`). A duplicated
  key is a structural defect in its own right, and the setter refuses an
  ambiguous address. What this adds is that the printed call fails before the
  setter can say what is wrong. The per-row rule here does not reach it.

## Guards added, and what retires them

- **`add()`'s one row per field of each metadata row.** It stops two checks
  reporting one field. It does not silence a signal: the field is still
  reported, once, under the first check that finds it. *Retires when:*
  nothing, while `review_metadata()` documents one row per field and the
  printed call names each field as an argument. If either changes, revisit it.

in my reading. The change removes only a second row for a field already
reported on the same metadata row. Every field reported before is still
reported. The existing blank and marker tests are unchanged and pass, and no
