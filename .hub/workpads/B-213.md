## What changed, and where

- **`_pkgdown.yml`**: `write_sdp_semantic_closure` is the first entry in the
  "EML and KNB" section, ahead of `write_eml_from_sdp` and `publish_sdp_to_knb`.
  Those are the functions it works with. Its Rd says it "produces the two files
  `write_eml_from_sdp()` and `publish_sdp_to_knb()` require and neither writes".
  The section description now ends "starting from the semantic closure both
  require".
- **`scripts/check-pkgdown-index.R`** (new). It fails (exit 1) when an export
  has no topic under `man/`, and when `pkgdown::check_pkgdown()` fails with
  every topic that documents an export treated as public. It exits 2 when it
  cannot run: pkgdown or pandoc missing, `NAMESPACE` unreadable, an
  `exportPattern()` it cannot resolve without loading the package, or no
  exports at all. That way "could not look" never reads as "found nothing".
- **`.github/workflows/pkgdown-index.yaml`** (new). It runs the script on every
  pull request and on pushes to `main`, with no path filter. It installs pandoc,
  R, and pkgdown with its hard dependencies only. metasalmon's own dependencies
  are not installed, because the check never loads the package.
- **The commit order is deliberate.** The check (`f2e8ac4`) lands before the
  index entry, so this pull request's first CI run shows the job failing
  against the index as it stands, and the next run shows it passing.

## Why the check is stricter than `check_pkgdown()` on its own

pkgdown 2.2.1's `check_missing_topics()` flags `!in_index & !internal`, and
its error message ends *"Either add to the reference index, or use
`@keywords internal` to drop from the index."* So plain `check_pkgdown()` passes
an exported topic that has been keyworded out of the index, which is the exit
this item rules out. The script builds pkgdown's own package object with
`as_pkgdown()` and sets `internal` to `FALSE` on every topic whose aliases
include an export. It then passes that object to `check_pkgdown()`, which
accepts a built object as is. So the index is resolved by pkgdown itself,
selectors included. If there is no `reference:` section, pkgdown's default
index lists every non-internal topic, so that case cannot pass vacuously
either. Measured on this tree: 66 exports, 64 topics, no topic marked internal,
and every export has a topic.
