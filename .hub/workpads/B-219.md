# Workpad — B-219

## Queue item

**B-219**: `accept_suggestion(iri = "REVIEW:")` passes the non-empty check and
records an accept whose IRI is empty.

The item file, `queue/items/B-219.yaml`, is the only home of its state and its
retirement condition, and this workpad restates neither. The metasalmonpy half
is `B-220`, a separate item, and nothing here does it.

One point where the dispatch and `HUB.md` differed: the dispatch asked for a
heartbeat about once an hour, and `HUB.md` step 5 says every
`heartbeat_minutes` (`queue/config.yaml`). `HUB.md` was followed.

## What changed and where

- **`R/review-console.R`, `accept_suggestion()`.** The check that `iri` is not
  empty moved from before `.ms_strip_review_iri()` to after it, so it reads the
  value the decision records. When the supplied value was not empty and the
  strip emptied it, the refusal adds one line saying that the marker is removed
  from an accepted IRI and nothing followed it. The `rank =` path is unchanged,
  and so is `apply_sdp_semantics()`: the condition asks for the fix at the
  source, and a guard there would have been the downstream patch it rules out.
- **`tests/testthat/test-review-console.R`.** One `test_that()` per spelling
  `.ms_strip_review_iri()` removes today, eight in all: the bare marker, the
  marker as the package writes it (`.ms_review_iri_prefix()`), lower case,
  mixed case, a space before the colon, a tab before the colon, leading spaces,
  and a form feed after the colon. `.ms_scalar_text()` trims spaces, tabs and
  newlines but not a form feed, so that last one reaches the strip's own
  `\s*`. Each test asserts first that the strip empties the spelling. A control
  shows that `iri = "review : <IRI>"` is still accepted and recorded without
  the marker.
- **`NEWS.md`.** A *Fixed* entry under *metasalmon (development version)*.
- **`knowledge/parity-deviations.md`** (the port section) and
  **`knowledge/roadmap.md`** (the release index, metasalmonpy's section). Each
  gains the owed port in the form the 2026-09-24 entries use, naming `B-220`,
  with no landed record, since `B-220` is not done.

No spelling the strip recognises was changed. Which spellings count as the
marker is `Q-63`'s ruling.

### The defect and what it did downstream

Measured on `main` `6f4c1e8`. Each spelling, passed as `iri`, recorded an
accept with `decision_iri` `""`, while `iri = ""` and `iri = "  "` were refused.
Through a package built by `create_sdp()` with a mocked `find_terms()`, the
same fixture `tests/testthat/test-metadata-write.R` uses:

```
term_iri before : "REVIEW: https://w3id.org/smn/SpawnerAbundance"  term_type before: "skos_concept"
accept(iri = "REVIEW:") + apply: applied
term_iri after  : NA  term_type after : "skos_concept"
                                    iri source     decision
1                                  <NA>   user     accepted
2 https://w3id.org/smn/SpawnerAbundance    smn not_selected
3       https://w3id.org/smn/Escapement    smn not_selected
rebuilt review: rows in slot = 2 ; replayed decisions = 0
```

So `apply_sdp_semantics()` discarded the draft IRI, wrote `skos_concept` for a
`term_iri` that was now empty, marked both retrieved candidates `not_selected`
and recorded an `accepted` row with no IRI. `review_semantics()` drops that row
(its `has_iri` filter), so the slot came back undecided with its draft gone.

With the fix, the same run refuses at `accept_suggestion()`: `term_iri` still
reads the draft `REVIEW:` IRI and `semantic_suggestions.csv` has no `decision`
column, because nothing was written.

## Found, not absorbed

1. **`B-202`'s port-record rule does not see `B-220` as a port.** The rule
   reads which ids are ports from the queue: an item in metasalmonpy whose
   `blocked_by` names a metasalmon item. Every other port in the two passages
   is filed that way (`B-215`, `B-216`, `B-230`, `B-240`, `B-241`, `B-242`),
   but `B-220` has `blocked_by: []`. Probed on a copy of this branch: with
   `B-220` set to `done`, `lint` passes, so the entries this branch adds would
   go on reading as owed after the port lands. With `blocked_by: [B-219]` and
   both items `done`, `lint` fails with `port-landed-unrecorded` at both
   entries. Setting that field is a queue change to another item, one that
   would also hold `B-220` until this merges, so it is not made here.
2. **Candidate: a shortlisted candidate whose `iri` is only the marker.**
   `review_semantics()` keeps it, because its `has_iri` filter
   (`R/review-console.R:281`) tests for a non-blank value, and
   `accept_suggestion(..., rank = 1)` then records `decision_iri` `""`, measured
   on this branch with the fix. A recorded `accepted` row with that `iri`
   replays the same way (`R/review-console.R:115`). No producer in this package
   writes such a row, so it needs a hand-edited or external suggestions table.
   metasalmonpy was not measured.
3. **Candidate: `iri = "REVIEW: REVIEW:"`.** The strip removes one marker, so
   the accept records `decision_iri` `"REVIEW:"`, a marker, measured on `main`
   and unchanged by this branch. It is not empty once stripped, so it is outside
   this item's condition.

## Guards added, and what retires them

- **The premise assertion in each per-spelling test**
  (`expect_identical(.ms_strip_review_iri(.ms_scalar_text(marker)), "")`). It
  fails, naming the spelling, if the strip stops removing it, so a narrowed
  strip cannot leave a test that checks nothing. *Retires when* `Q-63`'s ruling
  puts every detector behind one predicate: the list should then come from that
  predicate's ruled spellings rather than from this hand-kept one.
