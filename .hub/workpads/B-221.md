# Workpad — B-221

## Queue item

**B-221**: hand-picking the IRI of a lower-ranked candidate writes `term_type`
`skos_concept`, and re-applying the rebuilt review writes the candidate's own
type.

The item file, `queue/items/B-221.yaml`, is the only home of its state and its
retirement condition, and this workpad restates neither. The metasalmonpy half
is `B-222`, a separate item, and nothing here does it.

## What changed and where

- **`R/review-console.R`, `accept_suggestion()`.** With `iri =`, the decision
  went on the slot's first row whatever the IRI was. It now goes on the row of
  the first candidate in the slot whose IRI, trimmed and without the `REVIEW:`
  marker, equals the accepted IRI. That is the row `rank = <its rank>` uses,
  and it is where `review_semantics()` replays the decision after an apply. So
  `iri =` naming a shortlisted candidate returns the same review object as
  `rank =` (a test compares them with `expect_identical()`, marked and
  unmarked). An IRI no candidate in the review carries still goes on the first
  row. The `rank =` path is unchanged.
- **`R/review-console.R`, `.ms_review_decision_iri()`**, new. It gives a
  candidate's IRI as a decision records it: trimmed, with the leading
  `REVIEW:` marker removed, which is what `rank =` and a replayed decision put
  in `decision_iri`. `accept_suggestion()`'s selection above reads it, and so
  do the two comparisons below.
- **`R/metadata-write.R`, `apply_sdp_semantics()`**: two comparisons.
  - Its `term_type` branch takes the candidate's type when the decision row
    carries the accepted IRI. It compared the row's stored IRI, marker and all,
    with the unmarked `decision_iri`, and now reads the row's IRI through
    `.ms_review_decision_iri()`. Without that, a candidate stored as
    `REVIEW: <IRI>` was selected by `accept_suggestion()` and not recognised by
    the writer, and wrote `skos_concept` by `rank =` as much as by `iri =`.
  - The record mask, which picks the rows of `semantic_suggestions.csv` it
    marks `accepted`, stripped the marker without trimming. It now reads
    `.ms_review_decision_iri()` too. `readr::read_csv()` (2.2.0, vroom 1.7.1,
    the versions CI installs as well) trims spaces and tabs even inside quotes,
    but a quoted field keeps a `\n` or a `\r\n` at either end, which `trimws()`
    removes. So a candidate stored as `"<IRI>\n"` was selected and typed but
    missed by the record, which gave the IRI a hand-picked row. The rebuilt
    review then replayed that row, whose type nothing records, as
    `skos_concept`. Measured with `.ms_read_metadata_csv()`: `"<IRI>\n"`,
    `"\n<IRI>"` and `"<IRI>\r\n"` read back as written, while `"<IRI>\r"`,
    `"\r<IRI>"` and `"\t<IRI>\t"` read back trimmed.
- **The `iri` parameter's documentation** says that an `iri` a shortlisted
  candidate carries is recorded as that candidate. `man/accept_suggestion.Rd`
  is regenerated for that paragraph only. This machine's roxygen2 is 8.1.0 and
  the repository was built with 8.0.0, so `devtools::document()` also rewrote
  `DESCRIPTION`'s `Config/roxygen2/version` and reflowed two `importFrom()`
  blocks in `NAMESPACE`. Those two files were reverted.
- **`tests/testthat/test-metadata-write.R`**, a new section after B-176's with
  five tests on a fixture whose `spawner_count` variable slot holds an `smn`
  candidate and then an `owl_class` one (`type_iris` `owl#Class`):
  1. The condition's pin: hand-pick the rank-2 `owl_class` candidate's IRI,
     apply, rebuild with `include_filled = TRUE`, re-apply, and compare
     `column_dictionary.csv`'s raw bytes and the four managed files' digests.
     It asserts its premise first: the IRI is at rank 2, that candidate reads
     `owl_class`, and rank 1 reads `skos_concept`.
  2. `accept_suggestion(iri = <that IRI>)`, and the same IRI with the marker,
     give the review `rank = 2` gives.
  3. The rank-2 candidate's IRI stored as `REVIEW: <IRI>` in
     `semantic_suggestions.csv`: by `iri =` and by `rank = 2`, the write is
     `owl_class`, and a rebuild and re-apply leave the managed files as they
     were.
  4. The same candidate's IRI stored as `"<IRI>\n"`: by `iri =` and by
     `rank = 2`, the record marks that candidate `accepted` and has no `user`
     row, and after a rebuild and re-apply `term_type` is still `owl_class` and
     the managed files are unchanged. It asserts first that the newline
     survives `semantic_suggestions()`, so a reader that starts trimming it
     fails the premise rather than leaving a test that checks nothing.
  5. A control for B-176's case: every candidate is an `owl_class`, and an IRI
     none carries still writes `skos_concept`. It passes before and after. It
     is there so a later fix that takes the first row's type regardless fails.
- **`NEWS.md`.** A *Fixed* entry under *metasalmon (development version)*.
- **`knowledge/parity-deviations.md`** (the port section) and
  **`knowledge/roadmap.md`** (the release index). Each gains the owed port in
  the form the 2026-09-25 entries for B-56 and B-219 use, naming `B-222`. There
  is no landed record, since `B-222` is not done.
- **`queue/items/B-222.yaml`**: `blocked_by: [B-221]`, which was `[]`. #165 did

## Found, not absorbed

1. **Candidate, a pair: an IRI carried by a candidate outside the review's
   `max_candidates` window.** `accept_suggestion()` can only look at the review
   it is given, and `review_semantics()` drops every row past
   `max_candidates` (5 by default). So `iri =` naming a rank-6 candidate goes on
   the first row and writes `skos_concept`. `apply_sdp_semantics()` then marks
   the rank-6 row `accepted` in `semantic_suggestions.csv`, because its record
   mask matches by IRI across the whole slot. A review rebuilt at the default
   window shows no decision, which is `B-217`'s symptom. Rebuilt with
   `max_candidates = Inf`, it replays on rank 6, and re-applying writes that
   candidate's type. Measured on this branch, six candidates with an
   `owl_class` at rank 6:

   ```
   default review holds ranks 1,2,3,4,5
   iri = <rank-6 owl_class IRI>, default window: term_type skos_concept
   rebuilt at default window carries a decision: FALSE
   rebuilt at max_candidates = Inf replays on rank 6
   re-applied: term_type owl_class ; column_dictionary.csv identical: FALSE
   ```

   metasalmonpy `main` `2405df2` gives the same (`max_candidates=None` shows
   all): ranks 1-5, `skos_concept` then `owl_class`, bytes not identical. The
   same decision can therefore write two types, depending on the window the
   next review is built with. The condition names a *shortlisted* candidate, and
   `rank = 6` does not exist in a five-row review, so this is not B-221's. A fix
   would probably go in the writer, taking `term_type` from the package's own
   `semantic_suggestions.csv` rows for the slot, the same rows the record mask
   marks. That choice belongs to whichever item takes this up. It sits beside
   `B-217` and `B-218` rather than inside them: they are about what a review
   shows, and this is about what gets written.
2. **Candidate, a pair: two candidates in one slot carrying one IRI.** The
   record marks every row of the slot whose IRI equals the decision's as
   `accepted`, so it cannot say which one was chosen. The rebuilt review seeds
   an accept on each, and `.ms_review_decisions()` keeps the first. So
   `rank =` naming the later carrier writes that row's `term_type`, and the
   re-apply writes the earlier row's. `create_sdp()` keeps both rows when a
   search returns one IRI from two sources, so retrieval reaches this. The
   measurement is a slot with `smn` at rank 1, no type evidence, and `ols` at
   rank 2, typed `owl#Class`: `accept_suggestion(rank = 2)`, apply, rebuild
   with `include_filled = TRUE`, re-apply.

   ```
   == main 0ff9bff
   exact duplicate        rank = 2 writes owl_class; record accepted rows 1,2; replay on rank 1,2; re-apply writes skos_concept; identical FALSE
   duplicate + newline    rank = 2 writes owl_class; record accepted rows 1;   replay on rank 1;   re-apply writes skos_concept; identical FALSE
   == this branch 81debc7
   exact duplicate        rank = 2 writes owl_class; record accepted rows 1,2; replay on rank 1,2; re-apply writes skos_concept; identical FALSE
   duplicate + newline    rank = 2 writes owl_class; record accepted rows 1,2; replay on rank 1,2; re-apply writes skos_concept; identical FALSE
   ```

   metasalmonpy `main` `2405df2` gives the exact-duplicate line unchanged:
   `rank=2` writes `owl_class`, the record accepts rows 1 and 2, the replay
   lands on both, and the re-apply writes `skos_concept`. So this branch changes
   neither outcome. It only moves the newline variant from recording the wrong
   row alone to recording both. `iri =` naming such an IRI takes the first
   carrier, which is also where the replay lands, so B-221's own path is stable
   here. A fix has to choose how the record tells two rows with one IRI apart.
   Position in the slot moves when a hand-picked accept inserts a row at the
   head, which leaves `source`, the label, or something else. That choice
   belongs to the item that takes this up.

## Guards added, and what retires them

None. The five tests are regression tests, not suppressions, skips or
workarounds. Each one's premise assertions are there so that a change to the
fixture's ranking or to type inference fails loudly, rather than leaving a test
that checks nothing. They go when the tests go.
