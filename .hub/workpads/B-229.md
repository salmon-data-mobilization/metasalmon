# B-229 — Count failures hidden by successful CI reruns

## Instrument

`python3 scripts/ci-attempt-history.py --control-run-id 35105540412` uses the
existing GitHub CLI credential and only GET requests. It discovers reruns from
the returned pages of the selected workflow's available runs, then reads every
attempt of those reruns from
`/actions/runs/<id>/attempts/<n>`. A single-attempt run's listing already is its
only attempt, so no duplicate API read is needed for those runs. Output labels
run and attempt counts explicitly and details each rerun's history. The
caller-supplied ID is an independently known failed-then-successful rerun used
only to check that the listing and attempt reads reached it; the API still
discovers every rerun it counts. A missing or changed control stops the report
until another known rerun is supplied. API/schema errors also abort rather than
returning partial counts. Page overlap is deduplicated by run ID; live reads
are honestly described as a non-atomic observation. One control cannot prove
that every historical API page was returned or recover deleted runs.

The [official Actions API](https://docs.github.com/en/rest/actions/workflow-runs#get-a-workflow-run-attempt)
keeps the per-attempt conclusion without requiring a log download. No new
tracker, claim protocol, runtime package dependency or package capability was
introduced; this is a shared hub measurement tool, so no Python package port
or parity row is owed. The backlog names the instrument and observed counts.
