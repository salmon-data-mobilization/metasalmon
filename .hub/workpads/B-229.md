# B-229 — Count failures hidden by successful CI reruns

## Instrument

`python3 scripts/ci-attempt-history.py` uses the existing GitHub CLI credential
and only GET requests. It discovers reruns from every page of the selected
workflow's available runs, then reads every attempt of those reruns from
`/actions/runs/<id>/attempts/<n>`. A single-attempt run's listing already is its
only attempt, so no duplicate API read is needed for those runs. Output labels
run and attempt counts explicitly and details each rerun's history. API/schema
errors abort rather than returning partial counts. Page overlap is deduplicated
by run ID; live reads are honestly described as a non-atomic observation.

The [official Actions API](https://docs.github.com/en/rest/actions/workflow-runs#get-a-workflow-run-attempt)
keeps the per-attempt conclusion without requiring a log download. No new
tracker, claim protocol, runtime package dependency or package capability was
introduced; this is a shared hub measurement tool, so no Python package port
or parity row is owed. The backlog names the instrument and observed counts.

## Verification

Files were frozen before testing. Six offline tests cover hidden prior failures
across pages, several failed attempts within one recovered run, cancelled-first
control, single attempts, page overlap, incomplete attempts, API failure,
malformed/mismatched metadata, and read-only CLI pagination.

The live read discovers the positive controls without receiving their numbers
as inputs. It reports 902 available runs and 906 attempts: 32 failed runs in
the listing versus 35 failed attempts, with three failed attempts hidden by
successful reruns. Runs 337 (`34696100813`), 360 (`34912254547`) and 449
(`35105540412`) each show attempt 1 `failure`, attempt 2 `success`. Run 215
shows `cancelled`, then `success`, and is not a recovered failure. Four attempts
were still incomplete when observed; those are counted separately.

The shell Python lacks pytest; direct stdlib unittest execution passes.
The broader script checks use pytest through an isolated uv runtime, without
installing it into the user's Python environment. CI's existing hub-queue job
already collects this new test file.
That broad run passes 192 tests and 44 subtests in 9.34s. OKF capture has zero
diagnostics; `git diff --check` passes.
