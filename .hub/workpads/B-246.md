# Workpad — B-246

## Queue item

**B-246**: the R review console can still record an accept whose IRI is empty
or still a `REVIEW:` marker, and reports a suggestion row with an empty IRI as a
field it cannot decide.

The item file, `queue/items/B-246.yaml`, is the only home of its state and its
retirement condition (`retires_when`), and this workpad restates neither. The
condition's four cases are referred to below as (1) to (4), in its order. The
metasalmonpy half is `B-247`, a separate item, and nothing here does it. Which
spellings count as the marker is `Q-63`'s: every case is written against the
spellings `.ms_strip_review_iri()` and `.ms_is_review_iri()` recognise today,
and neither function changed.

## What changed and where

- **`R/review-console.R`, `.ms_review_names_term()`**, new. It takes an IRI as
  a decision records it (`.ms_review_decision_iri()`: trimmed, one leading
  marker stripped) and answers whether it names a term: not missing, not empty,
  and not still read as a marker by `.ms_is_review_iri()`. Both call sites
  below read it, so the queue and the refusal cannot disagree about what a
  decision may record. That disagreement, between a check and the strip, is
  what B-219 fixed.
- **`R/review-console.R`, `review_semantics()`.** `has_iri` is that predicate,
  where it tested only that `iri` was not blank. The list printed under *"Some
  suggestions target fields this review cannot decide"* is built from the rows
  with no write-back address or no IRI field (`!decidable`), where it was built
  from every dropped row (`!keep`).
- **`R/review-console.R`, `accept_suggestion()`.** The refusal calls the
  predicate instead of `nzchar()`, so a value that is still a marker once one
  is stripped is refused too. It has its own message: *"`iri` must be an IRI,
  not a `REVIEW:` marker."* The two B-219 messages are unchanged, byte for
  byte. Since the first Codex review it also runs on `rank =`, where it aborts
  with *"The candidate at that `rank` names no term."* `review_semantics()`
  queues no such candidate, so this is reached only by a review that function
  did not build as it is now: one saved by an earlier version, or edited by
  hand.
- **`tests/testthat/test-review-console.R`**, 34 tests after B-219's:
  - (1) per spelling in `marker_only_iris` (8): a candidate that is only the
    marker is not queued alone, so `accept_suggestion(rank = 1)` finds no slot;
    ahead of a real candidate it takes no rank, dropping it prints no "cannot
    decide", and `rank = 1` records the real IRI.
  - (2) per spelling (8): a recorded `accepted` row whose `iri` is only the
    marker replays no accept with an empty `decision_iri`, and the slot is
    queued again, undecided.
  - (3) per doubled spelling (4: `REVIEW: REVIEW:`, `REVIEW:REVIEW:`,
    `review : Review:`, and `REVIEW: REVIEW: <IRI>`): `iri =` refuses it; as a
    candidate it is not queued, so `rank = 1` records the real candidate, and
    a recorded accept of it replays no marker.
  - (4) for an empty and a missing `iri` (2): the row is not reported under
    "cannot decide" and the slot's real candidate is queued; beside a
    `dataset.csv` `keywords` row, the message still names `dataset.csv` and
    no longer names `column_dictionary.csv`.
  - (1) and (3) in a review the current `review_semantics()` did not build
    (12, every spelling of both lists): with a queued candidate's `iri` edited
    to the spelling, `rank = 1` refuses it. Added for the first Codex review.
  - Each per-spelling test asserts its premise against the strip and detector
    first, as B-219's do, and (1) and (2) reuse B-219's `marker_only_iris`
    rather than a second list.
- **`NEWS.md`**: a *Fixed* entry under *metasalmon (development version)*,
  including that a candidate the queue drops takes no rank, so the candidates
  after it in its slot rank one place higher.
- **`knowledge/parity-deviations.md`** (the port section) and
  **`knowledge/roadmap.md`** (the release index): the owed port, in the form
  B-219's and B-221's use, naming `B-247`, with no landed record.

## Which shape, and why each fix is the smallest

- **(1): never queue, not refuse in `accept_suggestion()`.** One changed line,
  `has_iri`. It is the smallest because the same line also closes (2):
  `.ms_review_seed_recorded_decisions()` replays decisions over the queued rows
  only. Refusing in `accept_suggestion()` would have closed (1) and left the
  replay recording the empty IRI, so it needed a second change in the replay.
  It is also how a blank `iri` was already treated: never queued, taking no
  rank. **The first Codex review found the route this shape leaves open:** a
  review object the current `review_semantics()` did not build, one saved by an
  earlier version or edited by hand, can still hold such a candidate, and
  `accept_suggestion()` checked only the class of what it was given. So the
  refusal now runs on `rank =` too. That is the other shape as a second layer,
  not a replacement: the queue filter is still what closes (2) and what keeps
  the console from printing a candidate it would then refuse.
- **(2): no change of its own.** Closed by (1)'s line.
- **(3): refuse, and do not strip again.** The predicate's
  `.ms_is_review_iri()` term closes the `rank =` and replay routes inside the
  same `has_iri` line, and the existing `iri =` refusal calls the predicate,
  plus one message branch (and the `rank =` refusal above covers a review that
  still holds one). Stripping repeatedly would have been a new rule about what
  counts as the marker, which is `Q-63`'s.
- **(4): build the report from `!decidable` rather than `!keep`.** Three index
  expressions change and nothing is added. The condition allows not reporting
  such a row. The row offers nothing to accept, and the slot's real candidates
  are queued as before, so no new message was written for it.
- **No exported signature, return-value attribute or column changed.** The
  review tibble has the same columns. `review_semantics()` returns fewer rows
  where a candidate names no term, and `accept_suggestion()` refuses more
  values. The 19-column target row is untouched.

## Guards added, and what retires them

- **The premise assertion in each per-spelling test.** (1) and (2) assert that
  the strip empties the spelling, and (3) that what the strip leaves is still
  read as a marker. Each fails naming its spelling if the strip or detector
  changes, so a changed strip cannot leave a test that checks nothing.
  *Retires when* `Q-63`'s ruling puts every detector behind one predicate: the
  lists should then come from it, as B-219's list should.
- The queue filter and the silent drop in (4) are behaviour rather than
  guards: a row that names no term offers nothing to decide, so nothing
  retires them.
