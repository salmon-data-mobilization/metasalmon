# B-256 — Make GitHub CSV error remedies reachable

## Change

`ms_github_get()` lets HTTP 401/403/404 reach its only caller,
`read_github_csv()`, which already owns PAT, SSO and missing-path guidance.
Other HTTP statuses and transport failures keep their normal failure path;
request authorization and retry settings are unchanged. The exception's
retirement condition is recorded beside it: remove it if those remedies move
into httr2's own error handler.

`test-github-http-status.R` uses httr2's real request boundary with offline
responses, rather than stubbing the package GET helper. It covers both token
states for 401/404 and all token/SSO combinations for 403, keeps tokens out of
error messages, and includes 400/500, transport and successful CSV controls.
The mock API version skip states its retirement condition.

No public signature, result attribute, version or ontology term changes. The
roadmap records why there is no Python port: current metasalmonpy `main` at
`e81cacd` already examines these statuses before `raise_for_status()` and its
request helper returns 4xx responses. This is R convergence with existing
Python behavior, not a new intentional divergence.
