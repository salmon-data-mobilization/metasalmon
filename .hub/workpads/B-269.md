# B-269 — Validate SSSOM columns against their actual ranges

## Changes

`R/sssom.R` removes three string fields and `predicate_type` from the identifier
list. Predicate types use the SSSOM entity-type enum in rows and propagated
metadata, excluding the two values explicitly forbidden for predicates. Other
reference checks and existing profile constraints remain. Four tests cover
each field, invalid types, all legal predicate types, metadata and package
write/read round-tripping. Roxygen, NEWS and two port passages are updated.

The type choices come from the existing SSSOM 1.1 profile's schema, not from
a validator accepting them: [source snapshot](https://github.com/mapping-commons/sssom/blob/667d3c579d92ad2e1a480503625eeef1e6af8e6d/src/sssom_schema/schema/sssom_schema.yaml).
No ontology term IRI is chosen, changed or removed.

## Separate finding

The B-137 scout observed that the existing SSSOM reference parser admits
U+3000 in an HTTP IRI under C locale and rejects it under C.UTF-8. That locale
defect is separate from column ranges and is recorded in B-137's workpad;
this change leaves it outside scope.

## Guards and retirement

No skip or workaround added. The predicate enum is maintained when this
profile adopts a schema with a changed enumeration. Existing structural/profile
constraints still apply to the text fields.
