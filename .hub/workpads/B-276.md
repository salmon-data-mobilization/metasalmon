## What changed and where

- **`R/semantic-suggestions.R`, `.ms_semantic_code_value_is_empty()`**, new. It
  is the rule's one predicate: a code value is empty when it is NA, or text that
  is blank once trimmed. The text `NA` is a code value, not an empty one.
- **`R/semantic-suggestions.R`, `.ms_semantic_discover_targets()`**. Its codes
  loop returns no target for a row the predicate reads as empty, in any role,
  before the role set is built. That loop is the one place a `codes.csv` target
  is formed (read: nothing else in `R/` builds one), so `suggest_semantics()`
  and `create_sdp()` inherit it. Other rows of the column keep their targets.
- **`R/review-console.R`, `review_semantics()`**. Its `keep` mask drops a
  suggestion row whose file is a code's (`.ms_review_is_code_slot()`) and whose
  code value the predicate reads as empty. This is the step every queued slot
  passes, and it is where a `semantic_suggestions.csv` written before the
  change is dealt with (next section).
- **`R/review-console.R`, comments.** Two said discovery still targets such a
  row; they now say only a review built before B-276 holds one. The comment on
  `.ms_review_resolve_slot()` still describes that function correctly and was
  left alone. `.ms_review_match_slot_rows()`'s file test is kept, unchanged.
- **`accept_suggestion()`'s `code_value` documentation** (roxygen and
  `man/accept_suggestion.Rd`): such a row has no slot at all, where it said a
  blank never selects one. The signature is unchanged. The Rd was regenerated
  in a throwaway copy of the tree with roxygen2 8.1.0 and only that file was
  taken: `document()` there also moved `Config/roxygen2/version` from 8.0.0 to
  8.1.0 and reordered `NAMESPACE` imports, which is churn this item does not
  own.
- **Tests.** `tests/testthat/test-semantic-suggestions.R`: two new tests.
  `tests/testthat/test-review-console.R`: three new tests, the round-trip test
  the condition names rewritten to its ruled form, and the
  `vocabulary_code_review()` fixture changed to build a review the way an
  earlier version did. Details under *Evidence*.
- **`NEWS.md`**, under the development heading's *Fixed*, after B-246's entry.
- **`knowledge/parity-deviations.md`** and **`knowledge/roadmap.md`**: the port
  owed to metasalmonpy, as the roadmap's rule for a new mirror debt requires, in
  both places, naming `B-277`.

## Where the old-CSV case is enforced, which `B-277` copies

**In `review_semantics()`, on the `keep` mask, from the same predicate
discovery uses.** A `semantic_suggestions.csv` written before the change still
carries such a row's candidates, and the item requires that the review queue no
slot for them.

- **The row is found by its file and its code value, never by its
  `target_row_key`.** The key spells the empty value three ways: `…/NA` from R's
  `paste()`, and `…/nan` or `…/` from metasalmonpy. The test writes all three.
- **It is dropped without a message**, like a candidate naming no term
  (B-246). The existing *"Some suggestions target fields this review cannot
  decide"* message would have told the user to edit `term_iri` on that row by
  hand, which is the opposite of the ruling.
- **Because the mask comes before everything else, the row is gone with
  `include_filled = TRUE` too**, and a decision recorded on it is not replayed.
- **The rows stay in the file.** `apply_sdp_semantics()` reads the CSV itself
  and rewrites only the slots a review decided (read, `R/metadata-write.R`).
- **Not in the `semantic_suggestions()` accessor.** It is exported and returns
  the attribute, list element or file as written. Filtering there would change a
  public return value, which is not what the ruling names. The ruling names
  what the review queues.
- **Pull request #194 (B-326) moves this body into `.ms_review_queue()`**, which
  both `review_semantics()` and its new `write_semantic_review_packet()` read.
  So once both merge, the packet leaves such a row out as well, by the same
  line. The hunk here (main lines 321–326) touches none of #194's hunks
  (257–262 and 410–434).

## Two choices settled from the repository

- **Whitespace-only text is empty.** The ruling names NA and empty text. A
  blank code value had no address either, because the console's `has_code`
  test trims (`.ms_review_match_slot_rows()`). The package's own blank test,
  `.ms_sdp_extension_is_blank()`, trims as well. metasalmonpy's `_is_missing()`,
  which the ruling's probe used, strips whitespace (`semantics.py:32–40` on
  `main` `c7be120`). And on disk the CSV reader trims such text to NA anyway
  (`.ms_read_metadata_csv()`, readr's default `trim_ws`). So it is one rule
  in both packages, with no fourth case for `B-277` to invent.
- **The text `NA` keeps its target.** `.ms_read_metadata_csv()` maps only an
  empty field to NA (`.ms_csv_na_token()` is `""`), so a code list read from a
  package can carry the text `NA`. It is metasalmonpy's text `nan` case, which
  `B-277`'s condition names.

## Found, not absorbed

1. **Candidate, needing a specification call: a `term_iri` already recorded on
   a `codes.csv` row with no code value.** Measured above: on main, when the
   column's own slot of the vocabulary slot's role was filled, the printed call
   decided the vocabulary slot. `apply_sdp_semantics()` then writes `term_iri`
   onto that row when it is its column's only code row, and aborts
   (*"A decision does not address exactly one metadata row"*) when there are
   more. That is read in `R/metadata-write.R`, not run. A hand edit can do the
   same. After this change nothing surfaces such a value: the review no longer
   queues the row, and no validator reads `term_iri` against `code_value`.
   Whether a codes row with no code value may carry a `term_iri` at all is a
   schema question, so it is not a mechanical fix.
2. **Candidate, the same rule's next reader:
   `detect_semantic_term_gaps()` still reports such a row.** Measured on this
   branch: suggestions recorded before B-276 for a vocabulary row, whose
   candidates are all non-`smn`, come back as `candidate_gap` rows keyed
   `demo-1/spawners/spawner_count/NA`, in all three roles, beside the coded
   row's. Rows from a fresh `suggest_semantics()` no longer do, because
   discovery forms no target. So only an old file or attribute reaches it. That
   is the path to `render_ontology_term_request()`, a term request for a row
   the ruling says has no code value for a term to represent. The fix would be
   the same predicate on that function's suggestions, in both packages. It is
   outside B-276's condition, which names discovery and the review queue.
3. **For whoever lands second of this and #194 (B-326):** re-run
   `tests/testthat/test-review-console.R` after merging the other. The hunks do
   not overlap, but the filter here ends up inside #194's
   `.ms_review_queue()`.
