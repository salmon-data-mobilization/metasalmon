## Where the line is between B-3, B-128 and B-31

Three items name the same two functions. This is what each owns, as this branch
leaves them.

- **B-3 (this item): the request.** Endpoint, method, the authorization and
  content-type headers, user agent, timeout, OpenRouter's attribution headers,
  sending it, checking the status, decoding the body and extracting the message
  text. That is everything the two functions duplicated, and it is what "one
  shared chat request builder" names.
- **B-128: the body.** Its condition asks for `.ms_chat_http_request()` to build
  its body through `.ms_llm_build_chat_request_body()`, with a temperature
  argument added to that builder, and a test that an `openai` GPT-5 config omits
  temperature on the chat path. Doing that here would have retired B-128 by
  absorption, so the chat path still passes its own
  `list(model, messages, temperature)`. **Every clause of B-128's condition is
  still unmet and still satisfiable after this branch**: the body is still the
  chat path's own, and the `list(content, data, raw)` shape and the normalizer,
  which B-128 requires be left untouched, are untouched. What this branch changes
  for B-128 is only where its edit lands: the `body` argument that
  `.ms_chat_http_request()` now hands to `.ms_llm_chat_completion()`.
- **B-31: the engine, and with it the return shape.** Whether chat
  decomposition's session engine converges with the semantic path decides
  whether `.ms_chat()` goes on returning the wrapped shape, and that shape is
  what the normalizer's wrapped branch serves. Untouched here.

## What changed, and where

- **`R/llm-semantic-helpers.R`** — two new internal functions beside the body
  builder. `.ms_llm_chat_request(config, body)` is the one builder: it returns
  the httr2 request, and is the only function in the namespace holding the
  endpoint path. `.ms_llm_chat_completion(config, body)` sends it, checks the
  status, decodes the body and returns `list(content, raw)` — the message text
  extracted but neither cleaned nor parsed, because the two callers parse it
  differently. `.ms_llm_chat_json_request()` is now: body builder, completion,
  strict parse. Same signature, same bare return, same abort on a non-object.
- **`R/chat-decomposition.R`** — `.ms_chat_http_request()` is now: its own body,
  completion, lenient parse. Same signature (the unused `response_schema` and
  `temperature = 0.2` included, because `.ms_chat_invoke_request()` reads the
  formals), same `list(content, data, raw)` return.
- **`tests/testthat/test-llm-chat-request.R`** (new) — five tests: both default
  request functions route through the builder; both put the same request on the
  wire apart from the body, across `openai`, `openrouter`, `openai_compatible`
  and `chapi`; each keeps its own return shape (two tests); and a namespace guard
  that fails if any function but `.ms_llm_chat_request()` holds the endpoint
  path. Nothing leaves the machine: requests are answered by
  `httr2::local_mocked_responses()`.
- **`knowledge/backlog.md` #3** — status line, a *FIXED* paragraph, and a
  correction of the two sentences the fix disproves.
- **`knowledge/orientation.md`** — duplication map item 5 rewritten: the request
  is shared, the body is not.
- **`knowledge/sequences/s7-architecture.md`** — the builder bullet said "mutually
  exclusive with the normalizer, so do it inside the curation work"; it now says
  what is left and who owns it, with the old wording kept as a dated note.
- **`knowledge/roadmap.md`** — metasalmonpy release index: B-3 owes no port, with
  the measurement. `AGENTS.md` requires the reason a change is not mirrored to be
  logged in the roadmap card.

**What did not move.** No exported signature, return-value attribute, frozen

## Findings that belong to other items

1. **The normalizer does not depend on the builders having been two — and the
   backlog said it did.** Entry #3 read "This divergence is *why* the review
   adapter needs a two-shape normalizer" and "doing so is **mutually exclusive**
   with keeping the adapter's dual-shape normalizer"; the S7 card sequenced the
   builder inside the curation work on that basis. Both assumed that converging
   the request builders meant converging on one *response* shape. The request
   and the shape its reply comes back in are separable: the shared builder
   returns unparsed text and each caller parses it its own way. The normalizer
   (`.ms_llm_review_response_data()`) stays because `.ms_chat()` wraps whatever a
   `chat_request_fn` returns — a string, a wrapped list or a bare one — into
   `list(content, data, ...)` before the review adapter sees it, while the
   semantic path hands the adapter what its request function returned. Corrected
   in place with a dated note in the backlog entry and the S7 card, because the
   fix is the evidence. It bears on **B-31**: the normalizer's wrapped branch is
   now visibly an engine question, not a transport one.
2. **Candidate, no item: R and Python put different requests on the wire, and
   neither parity register records it.** Measured 2026-09-23 against metasalmonpy
   `main` at `3f8349a`. Python's `request_json()` (`llm_review.py:415`) sends
   `model`, `messages`, `response_format: {"type": "json_object"}` and a
   configured `reasoning_effort`, with no temperature, only the authorization and
   content-type headers, and the `requests` default user agent
   (`llm_review.py:419-434`). R sends `temperature = 0` on the semantic path
   except to an `openai` GPT-5 model, `temperature = 0.2` on the chat path, never
   `response_format`, OpenRouter's `HTTP-Referer` and `X-Title`, and
   `User-Agent: metasalmon/<version>`. Grepping `knowledge/parity-deviations.md`
   and metasalmonpy's `PARITY.md` for temperature, `response_format`,
   `json_object`, reasoning effort, referer, `X-Title`, user agent,
   `request_json` and `chat/completions` finds nothing relevant (row 60 matches
   only on "billable LLM requests"). `AGENTS.md` calls an undocumented difference
   a contract violation even when the difference is fine, and whether JSON mode
   or a fixed temperature is the right side is a behavioural judgement, so the
   ruling is **Brett's** — a direction to rule, then register rows or ports. It
   is a decision about a *different* change: nothing in this branch alters what
   either implementation sends, so it is not a judgement left open inside this
   one. The roadmap note for B-3 points here rather than restating it.
3. **Candidate, no item: `scripts/theme-a-benchmark.R` builds a third chat
   request** (`:2106-2130`). It has reasons of its own — a distinct user agent and
   `X-Title`, and it records the provider's resolved model and response id and
   refuses a substituted model — but it re-states the endpoint, the
   authorization and content-type headers and the timeout, and so can drift from
   the request the package sends in exactly the way #3 described, in a harness
   whose point is to measure the package's review behaviour. It already reaches
   internals through `getFromNamespace()`, so it could build through
   `.ms_llm_chat_request()` and override only the two headers it wants different.
   The guard added here cannot see it: it walks the package namespace, and says
   so in its header.
4. **`.ms_chat_http_request()` accepts `response_schema` and ignores it**, before
   this branch and after. `.ms_chat()` and `.ms_chat_invoke_request()` thread it
   through, no caller passes anything but `NULL`, and `chat_decomposition()` does
   not expose it, so it is dead plumbing rather than a silent no-op a user could
   reach. It belongs with **B-31**, which owns the engine's request contract.
5. **B-152 is live in this container.** Under `NOT_CRAN=true` the two
   token-guarded tests in `tests/testthat/test-github-helpers.R` (`:161`,
   `:264`) error with `HTTP 404 Not Found` from `ms_github_get()`, identically on
   the unchanged tree and on this branch. Nothing new about B-152; recorded so the
   two errors in the full-suite table above are not read as this change's.
6. **Candidate, no item: parallel agents share one scratch directory, and generic
   file names in it collide.** The scratchpad a dispatched agent is told is
   "session-specific" is the orchestrator's, shared by every agent it dispatches.
   Measured 2026-09-23: while this item was open, B-198's agent wrote its own
   pull-request draft to the same `pr-body.md` path this agent had just written
   to, and earlier transcripts show `before.txt`, `after.txt` and
   `commit-msg.txt` reused across B-49, B-111, B-115 and others. Nothing was lost
   here — every overlapping transcript but B-198's was days old, and B-198
   rewrote its file after this agent's write — but an evidence file overwritten
   by a sibling fails silently, the same way a push to the wrong remote does.
   This agent's files now live in a `B-3/` subdirectory. The fix is one line in
   `.hub/agent-brief.md` or `HUB.md` § *Isolation*: scratch files go under
   `<scratchpad>/<queue-id>/`.

## Guards added, and what retires them

1. **The single-builder guard** — `chat_request_builders` and the namespace walk
   in `tests/testthat/test-llm-chat-request.R`. It fails if any function but
   `.ms_llm_chat_request()` holds the string `/chat/completions`. **Retires
   when** metasalmon stops building chat requests itself — transport handed to a
   client library, or to an engine that owns it (B-31 asks whether one should).
   A provider that genuinely needs a different request is added to the list with
   its reason rather than routed around it. Its limitations are stated in its
   header: it matches a string constant, so a path assembled from pieces evades
   it, and it cannot see `scripts/`.
2. **`skip_if_httr2_older_than()`** — skips a test on httr2 older than 1.0.0
   (`local_mocked_responses()`) or 1.2.0 (the `req_get_*()` accessors), because
   DESCRIPTION pins neither. **Retires when** DESCRIPTION's Imports requires
   httr2 (>= 1.2.0). It skips nothing on this machine or on CI.
