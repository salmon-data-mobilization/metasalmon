# B-338 — Record a shared member hand-back shown in chat

## Change

`hub done ID --chat` appends a child handoff commit to the existing claim ref
after confirming that the queue checkout is current and the item's configured
member has `solo: false` or no `solo` key. The new `claim.yaml` tip retains
`id`, `agent`, `action: handoff`, `lease_until`, and `attempt`; it has no
`branch` key and has the exact `reason: hand-back in chat`. The claim stays
held. A solo member or an unrecognized participation value is refused before
any claim-ref push. The existing `--branch` handoff and its exact branch-name
check remain in place.

`HUB.md` step 7 now names the chat option instead of telling an agent to keep
heartbeating finished shared-repository work. The hand-back section and
command help state the record shape and current-checkout requirement. The
deployed `hub status` helper must recognize only this exact reason when a
handoff has no branch; an arbitrary branchless handoff remains unknown. The
helper's compatibility change is separate from this item.

## Scope and handoff

This changes the hub client and its policy, not either package's data behavior;
the metasalmonpy parity contract does not require a Python package port. `NEWS`
records the observable command change. HUB.md class 7 reserves the resulting
pull request for Brett's merge review. No member work branch or pull request
is published by `--chat`; the agent shows the diff and complete proposed pull
request text in chat first.
