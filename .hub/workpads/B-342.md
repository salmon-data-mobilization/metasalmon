## Parsed CSV boundary and guard retirement

The package's existing `readr::read_csv(trim_ws = TRUE)` metadata reader
strips leading ASCII spaces before strict validation sees a CSV field. A peer
confirmed that a raw `tables.csv` value ` https://example.org/thing` therefore
reaches this validator as `https://example.org/thing` and passes. B-342 checks
the parsed metadata value, as its pinned no-break-space regression does;
changing the shared reader or duplicating raw CSV parsing is outside this
claim. This limit is stated here rather than calling the raw-byte case fixed.

The new table collector excludes method/protocol fields only while the
existing placement collector validates them; that exclusion retires if the
placement check is consolidated into this collector. It excludes recognized
REVIEW markers only while the dedicated marker collector owns them; B-344's
marker-definition change must keep those two paths aligned. Exact missing
values retain the existing checks, while whitespace-only text is malformed.

correction. The dictionary now checks each constraint component
with the existing absolute-IRI predicate, trimming ASCII spaces only beside
the semicolon and preserving outer whitespace and empty components as invalid.

marker report in strict validation and in `review_metadata()`. The other five
dictionary semantic fields and table fields remain single IRIs. The table
collector now skips exact empty cells only; the required observation-unit
blank path remains its separate owner. The metadata CSV reader still trims
leading ASCII spaces before validation; this patch does not change it.
