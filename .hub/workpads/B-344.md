Q63, answered by Brett on 2026-09-25, defines a marker as optional ASCII space
or tab, ASCII-case REVIEW, optional ASCII space or tab, then a colon. Stripping
also removes ASCII space or tab after the colon and nothing else. The shared
predicate and strip in `R/package-helpers.R` implement that definition without
locale-sensitive case or whitespace classes. Table/dictionary/placement scans,
extension and migration readers, bundle-selected IRIs, and both serialized XML
guards use it. The XML guards scan whole documents conservatively with an
unanchored derivative of the same spelling.

The review console needed an additional raw-input correction: its previous
scalar trim converted an excluded leading newline into a marker before the
strip. Decisions now check the raw marker first, retain characters left after
the colon, and keep the former trim for ordinary IRIs unless trimming would
newly create a marker. `apply_sdp_semantics()` writes the recorded decision
bytes without a second trim. No public signature, frozen column, IRI choice,
numbered parity row, version, provider path or model-call path changes.
B-345 owns the Python half; no new parity row is owed once both halves land.
