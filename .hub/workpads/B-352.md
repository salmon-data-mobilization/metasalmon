# B-352 — refuse YAML tags in embedded SSSOM metadata

## Scope and ruling

Q62 rules that the SSSOM metadata profile has no use for YAML tags. The R
reader now probes the embedded metadata with a non-evaluating YAML parse that
retags exclamation tokens to one private handler; libyaml decides which tokens
are actual node properties. A bulk parse handles ordinary inputs; when one
replacement might hide another, each exclamation mark is probed separately.
A tagged value is refused with an error naming the mapping-set file. Public
`read_sssom_mapping_set()` and `validate_salmon_datapackage()` both reach that
check. Ordinary exclamation text, quoted leading exclamation text, and
literal block text remain readable. The ordinary loader still parses valid
YAML with `eval.expr = FALSE`; the probe does not evaluate tag expressions or
return its transformed values.

B-353 owns the metasalmonpy mirror in the same stream. No public signature,
SSSOM schema, ontology IRI, frozen semantic row, or parity deviation changes.
Python's existing restricted YAML reader does not support R's multiline or
block scalar cases; those R preservation tests protect R's existing behavior,
not an expansion of the Python parser.

## Review fix for literal exclamation performance

The requested Codex review on PR 255 found a real cost in the confirmation
fallback: after a bulk probe found no tag, it reparsed the whole metadata once
for each `!`, including bangs that are plainly inside a complete quoted value,
comment, or simple block scalar. A public-reader test counted 82 native YAML
parses for an 80-bang ordinary value (including the reader's final parse); the
first RED run had four count failures. A peer then found three more ordinary
valid shapes with the same cost: plain scalar, quoted flow item, and multiline
quoted scalar. Their public-reader cases and later-tag siblings added six RED
count failures, each at 82 parses. A mask of only simple literal lines did not
retire the performance finding and was superseded before publication.

The source now gives every possible tag token a private spelling in a
**disposable probe** without consuming quote or flow delimiter characters.
One native YAML parse invokes handlers only for spellings that libyaml sees as
node tags. A built-in name such as `str` is made private so implicit strings
cannot trigger a false refusal. The original metadata still goes to
`yaml::yaml.load()` unchanged. A bounded peer then found two quoted `!`
values whose closing apostrophe was accidentally changed by the candidate
probe, hiding a later real tag. Public-reader siblings failed RED 2 and pass
when punctuation is kept verbatim. Three percent-encoded tag spellings also
failed RED 3: libyaml decodes the handler name, so handler keys now undergo
that one decode; matching quoted literal spellings remain accepted.

The focused SSSOM suite passes 169 assertions, zero failures, warnings or
skips; bare non-specific tags and a custom `%TAG` handle are also refused,
and all twelve high-bang public-reader cases stay at no more than three
native parses. A public two-document control proves the native handler also
sees a tag after `---` even though `yaml.load()` returns only the first
document; an untagged second document remains accepted. No document splitter
was added. This is a performance repair within Q62's already ruled tag
refusal, not a wider YAML grammar or changed metadata value. Frozen review
inputs: `R/sssom.R` SHA-256

`tests/testthat/test-sssom.R` SHA-256

An independent bounded peer read on the exact source hash above and the prior
test hash `b627a8e6` found no concrete defect before the final two-document
control was appended; the source hash was unchanged. Its public probes covered
quoted encoded text, encoded custom-handle
and bare tags, flow text followed by a real tag, and quoted text followed by a
real tag. Each 80-bang plain, flow, multiline and block literal made two
native YAML loads through the public reader; a real tag after quoted bangs
