# B-352 — refuse YAML tags in embedded SSSOM metadata

## Scope and ruling

Q62 rules that the SSSOM metadata profile has no use for YAML tags. The R
reader now probes the embedded metadata with a non-evaluating YAML parse that
retags exclamation tokens to one private handler; libyaml decides which tokens
are actual node properties. A bulk parse handles ordinary inputs; when one
replacement might hide another, each exclamation mark is probed separately.
A tagged value is refused with an error naming the mapping-set file. Public
`read_sssom_mapping_set()` and `validate_salmon_datapackage()` both reach that
check. Ordinary exclamation text, quoted leading exclamation text, and
literal block text remain readable. The ordinary loader still parses valid
YAML with `eval.expr = FALSE`; the probe does not evaluate tag expressions or
return its transformed values.

B-353 owns the metasalmonpy mirror in the same stream. No public signature,
SSSOM schema, ontology IRI, frozen semantic row, or parity deviation changes.
Python's existing restricted YAML reader does not support R's multiline or
block scalar cases; those R preservation tests protect R's existing behavior,
not an expansion of the Python parser.

- Independent read found five more observed RED results: tags after a plain

  it was replaced with the parser-handler probe. The next GREEN passed 110.
  A further quoted exclamation token and `%TAG` primary-handle control were
  RED with three failures, then GREEN with 113 assertions after the probe
  avoided consuming quote boundaries and omitted tag directives from its
  throwaway parse. A verbatim-looking literal swallowed a later tag in three
  more public RED cases, and a plain bang in a flow key swallowed a tagged
  value in one public RED case. The final bulk-plus-individual probe passes
  118 assertions with zero failures, warnings, or skips. These cases are
  public-reader tests, not scanner-only tests.
- Tagged controls cover local, standard, verbatim and anchored tags, nested and
  flow values, explicit `?` keys, and multiline flow. Literal controls cover
  single/double quotes, plain text with `!`, flow text, a literal block, and
  quoted text spanning physical lines. The public-validator `!expr` case
  installs a checksum-bound mapping set and verifies that its sentinel file
  was not created.

The node-property boundary follows YAML 1.2.2 section 6.9, "Node Properties":
<https://yaml.org/spec/1.2.2/#69-node-properties>. `yaml::yaml.load()` remains
the grammar and value parser in both the disposable probe and normal read.
The full R package check and exact-head CI remain publication gates.

## Review fix on the published draft

Claude review of `e9cd273` identified a valid missed tag: libyaml accepts
`!foo'bar X`, but the probe stopped its tag token at the apostrophe. The
public reader returned the value rather than refusing the tagged metadata.
Four new public-reader cases (scalar, flow sequence, mixed quoted/tagged
sequence, and flow mapping) failed before the fix: 4 failures, 120 passes.
The probe now includes an apostrophe in its disposable tag token while still
leaving double quotes and backslashes as boundaries. Quoted scalar and quoted
flow controls remain readable. The handler map also uses
`stats::setNames()` explicitly. The focused SSSOM suite passes 124 assertions
with no failure, warning, or skip; `scripts/check-pkgdown-index.R` passes 68
exports and 64 documented topics, and `git diff --check` passes. Strict local
`rcmdcheck::rcmdcheck(args = "--no-manual", error_on = "warning")` passed in

and generated site need no change for this same tag-refusal behavior.
