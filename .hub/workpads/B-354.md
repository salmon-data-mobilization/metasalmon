# B-354 — EML temporal coverage for an SDP instant

## Scope and ruling

The ruled SDP instant is `YYYY-MM-DDThh:mm:ssZ`. EML 2.2.0 represents one
date/time with a `calendarDate` followed by an optional `time`; its
`calendarDate` does not accept the whole instant. In `R/eml-export.R`,
`.ms_eml_add_coverage()` now sends each endpoint through one small helper. It
reads the package's persisted text once, splits only the complete ASCII
profile instant at its single `T`, and writes the two parts. Joining them with
`T` reproduces the original cell. Years, dates and malformed/out-of-profile
text keep the original `calendarDate` path. The two range ends are independent.

This is the R half of the ruling. B-355 owns the same behavior in metasalmonpy;
no parity deviation, ontology IRI, public signature or frozen row changes.

  assertions; `devtools::test(filter = "eml-export")` passed with its existing
  placeholder-metadata warning.
- RED: the new public `write_eml_from_sdp()` instant regression exited 1 before
  the production edit. EML's schema rejected both whole instant strings in
  `calendarDate` as not `resource:yearDate`.
- GREEN: the canonical-date tests pass with public-writer EML schema validity,
  exact date/time elements for both instants, and byte-exact reconstruction
  against `metadata/dataset.csv`. Mixed date-to-instant and instant-to-date
  ranges pass through that same public writer and schema. Direct builder
  controls leave trailing/multiple `T`, fractional/offset time, and a trailing
  newline unchanged in `calendarDate` with no `time` child. The surrounding
  EML export tests pass with only the same pre-existing warning.
