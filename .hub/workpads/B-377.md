## The choice: a warning, not an error

The retirement condition leaves it to the fix, and B-378 copies it. A warning,
for three reasons.

- **The return value does not change, and an error would change it.** B-57
  made the find helpers return the empty result for an outage rather than
  abort, which is what the list helpers had always done and what metasalmonpy's
  helpers do (its workpad, item 4, and *Found, not absorbed*). An error would
  change what all four exported functions give for an outage, from a tibble to
  a condition, which B-57's ruling did not cover: it went the other way. A
  warning leaves the return contract exactly as B-57 left it and adds the one
  thing that was missing, a signal.
- **A caller that expects a data frame keeps working.** A script that loops over
  code types during an outage gets empty tibbles, as before, and now a trace of
  each failed request in its log.
- **It is the answer the package already gives to the same problem.**
  `find_terms()` warns that a source *did not answer* and still returns its
  table, and the comment above `.ms_signal_search_failure()` states the rule
  both follow: a failed lookup must never be indistinguishable from a
  successful empty one.

The warning carries no condition class, as none of the package's other
`cli_warn()` calls does.
