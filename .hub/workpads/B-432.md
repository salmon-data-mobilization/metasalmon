# Workpad — B-432

## Scope and evidence

The queue item is `queue/items/B-432.yaml`; its retirement condition remains
authoritative there. Single-ID scope: B-350 is the only other claimable item
and the item itself says not to decide its quote-decoding question here.

The direct SSSOM reference parser in `R/sssom.R` (`.ms_sssom_validate_reference()`
and `.ms_sssom_is_unambiguous_uri()`) wrote `[[:space:]]` itself in four
places. Under `LC_CTYPE=C` TRE resolves that class as ASCII-only, so a
reference containing U+3000 was accepted there and refused under UTF-8.

Fixing the class alone was not enough. Measured on the first attempt: with the
shared class in place, the C-locale test still accepted U+3000 in
`subject_source` and refused U+00A0 in a mapping CURIE. The reader builds its
text with `rawToChar()`, which marks it native; under C a regex then matches
it byte by byte, so the multibyte members of the class become byte ranges and
NBSP's `A0` byte falls inside one. The reader now marks the text UTF-8 after
its existing `validUTF8()` check. `bytes` is untouched, so the writer's bytes
and the manifest hashes do not change.

The change:

- `R/iri-predicates.R`: the whitespace class is one constant,
  `.ms_iri_space_class`, and `.ms_absolute_iri_shape()` builds from it.
- `R/sssom.R`: the four direct-parser expressions build from the same
  constant; the decoded text is marked UTF-8.
- Python already uses `R_SPACE_CLASS` in its `sssom` module, so no runtime
  change is owed there. Both registers' row 28 described R as "one shared
  predicate"; R's row is amended here, and metasalmonpy's row gets a companion
  documentation pull request.
