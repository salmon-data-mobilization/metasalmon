## What changed, and where

1. **Units named by a column-name suffix** (`R/semantic-suggestions.R`,
   inside `.ms_semantic_discover_targets()`).
   - New `trailing_unit_token()` reads the last token of a column name or
     label. `mm`, `cm` and `kg` (and their spelled-out forms) are read
     directly. `m`/metre and `g`/gram are read only when a length word
     (`length`, `depth`, `height`, `width`, `distance`, `elevation`, ...) or a
     mass word (`weight`, `wt`, `mass`) comes before them. `cms`, `m2` and
     `km/h` are not read here. A compound unit is not read either: a `/`
     before the last token (`mercury_mg/kg`), or a token before it that is
     `per` or another unit (`mercury_mg_kg`, `eggs_per_kg`), means the last
     token is only a ratio's denominator. This was added in the first review
     round, after Codex showed that `mercury_mg/kg` drafted kilogram.
   - `extract_measurement_header_unit()` tries that token after its existing
     parenthesis, whole-text and "in X" checks.
   - `normalize_measurement_header_query()` drops a recognized unit token, so
     the variable query for `fish_length_mm` is `fish length`.
   - `is_count_like_measurement()` returns FALSE for a name that has a
     physical-quantity word (length, weight, mass, depth, height, width,
     diameter, girth, distance, temperature) unless it also has an explicit
     count word. Before the fix, "fish" plus a numeric type made
     `fish_length_mm` count-like, so its variable, property and unit queries
     were all `count`.
2. **Temporal coverage ignores administrative dates**
   (`R/dictionary-helpers.R`).
   - New `.ms_is_administrative_date_column()` tokenizes a column name
     (camelCase, `_`, `.` and glued date affixes such as `DateCreated`,
     `processdate`, `lastmodified`) and flags processing, created, modified,
     updated, edited, loaded, imported, inserted, uploaded, submitted,
     received, QC, verified, audited and exported dates. `entry`/`entered` is
     administrative only alone or as "data entry". `river_entry_date` is an
     observation.
   - `infer_dataset_metadata_from_resources()` drops those columns before it
     takes the minimum and maximum. If only administrative dates are present,
     the coverage stays blank. It does not fall back to them.
3. **Positive-longitude review note** (`R/dictionary-helpers.R`).
   - New `.ms_longitude_sign_is_suspect()`: every longitude in [50, 180] and
     every latitude in [30, 75], which is the mirror of the North American
     salmon range. The floor of 50 keeps Norway and the Baltic out.
   - When the check is true, `spatial_extent` becomes a `REVIEW REQUIRED:`
     note that contains the inferred extent unchanged. The existing strict
     placeholder sweep, `review_metadata()` and the setters already handle
     that marker. The sign is never changed.

Tests: `tests/testthat/test-create-sdp-inference-cues.R` (11 tests). NEWS: three
entries under the development heading. The owed port is recorded in the
`knowledge/roadmap.md` metasalmonpy release index and in a port passage in

## Not done, and why

- **metasalmonpy port.** metasalmonpy has all three gaps: `metadata.py`
  `infer_dataset_metadata_from_resources()` uses the same date-name pattern and
  writes the extent without a check, and `semantics.py`
  `_is_count_like_measurement()` mirrors the count fallback. The port is
  B-441. It is a port that is owed, not a deliberate difference. The first
  version of this pull request kept the parity note in its body only. Codex's
  first review found that this misses the mirror contract's requirement to log
  a deferral in the roadmap, so round 1 added a roadmap paragraph and a port
  passage in `knowledge/parity-deviations.md`. Neither adds a numbered register
  row.
- **Units beyond length and mass.** Temperature (`temp_c`), area (`area_m2`),
  flow (`flow_cms`) and other suffix units were not added. The whole-text
  patterns still catch `deg c`, `celsius` and the parenthesized forms.
- **Year-only columns.** A `year` column parses to no dates, so a year-only
  dataset still gets no temporal coverage. This was the case before, and it
  is not in this scope.
- **The window is a heuristic.** Correct data from Japan, the Russian Far East
  or the Pechora basin lie inside the window and get the note too. The user
  must replace the note with the confirmed extent. This is the cost of
  not changing the sign silently.

## Guards added, and what retires them

- `.ms_longitude_sign_is_suspect()` (the review note). Retires when the
  spatial extent is inferred from coordinates that declare their own sign
  convention (a geometry with a CRS, or an explicit hemisphere column), so a
  bare positive number is no longer the only evidence. The same text is in the
  code comment.
- The one-letter `m`/`g` quantity-word gate and the `entry` qualifier rule are
  scope limits on new readers, not suppressions. Each is stated in its code
  comment.
