  - New `.ms_measurement_name_tokens()` and `.ms_temporal_name_tokens()`: the
    two word lists, each moved out of the one function that held it so that

- `tests/testthat/test-year-shaped-measurement-role.R` (new, 6 tests, 81
  expectations):
  1. Nine year-shaped measurement fixtures, all typed `measurement`. They cover
     double, character and integer storage, and each kind of whole-word
     evidence: a measurement word, a sample size, a word followed by a unit, and
     a word joined to the rest of the name by punctuation (`Water depth(mm)`,
     `adult/count`).

     storage type, does not change the role. This includes an explicit factor,

### Why whole words, and not the existing measurement hint

This design choice is settled by a measurement. The obvious fix is to let
`.ms_name_has_measurement_hint()` exempt a column from the year check. I tried
it against every CSV in the four local ecosystem checkouts before choosing:
metasalmon, metasalmonpy, smn-data-pkg and salmon-domain-ontology, 112 files and
1,271 columns, 35 of them year-shaped. It moves **18** columns, and **every one
is a rightly temporal `temporal_start` / `temporal_end`** in an SDP
`metadata/dataset.csv`, because the hint's substring pattern finds `temp` in
`temporal`. The unit pattern has a bare `g` alternative, so it accepts any
parenthetical containing a `g` (`Cohort (Aug)`, `Season (spring)`,
`Start (beginning)`). The whole-token rule moves **none** of the 1,271. So the
broad rule would only have regressed real columns, since the corpus contains no
year-shaped measurement column. The defect is latent, and the fix is aimed at
the data it would meet.

Residual, stated in NEWS: a name whose only measurement evidence is a substring
(`ADULTCOUNT`) or a unit in parentheses (`Mass (kg)`) still types `temporal`
when its values look like years.

### Finding 1 (P2): punctuation-joined measurement words

> `Water depth(mm)` or `adult/count`: `.ms_name_tokens()` yields `depth(mm)` or
> `adult/count`, so the exact token check returns false and this branch
> classifies the column as `temporal`.

**Verified, and valid.** On `86444b7`, `Water depth(mm)` and `adult/count`
with values 1850 and 1920 type `temporal`, and `measurement` off the year range.
`.ms_name_tokens()` splits only at spaces, `.`, `_`, `-` and case changes.

**The same probe found a second defect, in my own round-0 patch, which Codex
did not raise.** `Escapement (yr)` typed `measurement` on `86444b7`, while `main`
types it `temporal`. The coarse token `(yr)` hides the year word from the
name-temporal check, while `escapement` is exposed to the measurement check. So
the patch had moved a name that contains a year word. A fix that split
punctuation only when looking for measurement words would have done the same to
`count/year`, while `count_year` stays temporal.

**The fix handles both.** The exemption now reads the name's words
(`.ms_name_words()`: the tokens split again at every ASCII punctuation
character). It applies only when those words include a measurement word and no
date or time word. After the fix:

```

adult/count            words=[adult,count] role(year)=measurement role(off-range)=measurement
Escapement (yr)        words=[escapement,yr] role(year)=temporal    role(off-range)=measurement
count/year             words=[count,year] role(year)=temporal    role(off-range)=measurement
adult/spawners         words=[adult,spawners] role(year)=attribute   role(off-range)=attribute
```

The output was identical under `LC_ALL=C.UTF-8` and `LC_ALL=C`. `adult/spawners`
types `attribute` both ways, so the invariant holds, but it does not reach
`measurement`. The downstream measurement hint does not recognise `spawners`

## The mirror

was touched.
