### Why whole words, and not the existing measurement hint

This design choice is settled by a measurement. The obvious fix is to let
`.ms_name_has_measurement_hint()` exempt a column from the year check. I tried
it against every CSV in the four local ecosystem checkouts before choosing:
metasalmon, metasalmonpy, smn-data-pkg and salmon-domain-ontology, 112 files and
1,271 columns, 35 of them year-shaped. It moves **18** columns, and **every one
is a rightly temporal `temporal_start` / `temporal_end`** in an SDP
`metadata/dataset.csv`, because the hint's substring pattern finds `temp` in
`temporal`. The unit pattern has a bare `g` alternative, so it accepts any
parenthetical containing a `g` (`Cohort (Aug)`, `Season (spring)`,
`Start (beginning)`). The whole-token rule moves **none** of the 1,271. So the
broad rule would only have regressed real columns, since the corpus contains no
year-shaped measurement column. The defect is latent, and the fix is aimed at
the data it would meet.

Residual, stated in NEWS: a name whose only measurement evidence is a substring
(`ADULTCOUNT`) or a unit in parentheses (`Mass (kg)`) still types `temporal`
when its values look like years.

### Finding B: method words outrank measurement words

> When punctuation joins a method word to a measurement word, such as numeric
> `enumeration/abundance` or `method/spawners`, this check now sees the
> measurement word through `name_words`, but the higher-priority method check
> still reads unsplit `name_tokens`.

**Valid, and caused by round 3's fix.** Round 3 let the sample-size and
measurement checks read the split words, but the method check (and the
identifier and temporal-name checks, which also outrank them) still read the
coarse tokens. So `method/spawners` became `measurement` for any values, where
`main` types it `attribute`.

**The class, not the instance.** Having the method check read words would fix
this instance. It would leave the identifier and temporal-name checks exposed in
the same way, and the next round would find `spawners/id`. So the consistent
version, where every check in `infer_column_role()` reads the split words, was
measured first. Over the 1,271-column corpus it changes nothing. But on eight
realistic unit and rate headers it changes six:

```
                      main         every check reads words
Discharge (m3/day)    measurement  temporal
Catch (fish/day)      attribute    temporal
Escapement (fish/yr)  measurement  temporal
Rate (per day)        measurement  temporal
Fish (no./site)       attribute    identifier
Spawners/year         attribute    temporal
Density (fish/m2)     measurement  measurement
Adults (no./km)       attribute    attribute
```

A slash or a parenthesis usually introduces a unit or a denominator, and the
time and number words inside one (`day`, `yr`, `no.`) are not what the column
is. The coarse tokenizer's refusal to split them is what keeps these headers
right. Splitting the name therefore cannot be made consistent across the role
checks without either those regressions or a tokenization policy for each check,
and that is a design question about every column's role, not about year-shaped
values. HUB.md says not to widen a claimed item's scope, so it is candidate 6
below.

**Fix: round 3's widening is reverted.** The split words are used only to
decide whether the year shape may decide. Every role check after that reads
the coarse tokens, exactly as on `main`, so an exempted column gets exactly the
role it gets off the year range. `method/spawners` and `enumeration/abundance`
are `attribute` again, on and off the year range. The cost is the round-3 names:
year-shaped `adult/spawners`, `fish/weight` and `sample/size` now type
`attribute` rather than `temporal`, and not `measurement`. That is what those
names get for any values on `main`, and the tokenizer question decides it.
Round 3's thread gets a follow-up reply saying the fix was reverted, and why.
