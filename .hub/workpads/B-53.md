## What I changed and where

- `R/dictionary-helpers.R`
  - `infer_column_role()`: the temporal branch is split in two. The name and
    type checks (a date/time/year token, `Date`, `POSIXt`) come first and are
    unchanged. The year-shape check, `.ms_values_look_yearish(col)`, now returns
    `temporal` only when `!.ms_name_has_measurement_token(name_tokens)`.
    Everything else in the function is unchanged, the branch order included. A
    column with a measurement word in its name and year-shaped values now goes
    through factor, method, sample-size, measurement and code-list checks, which
    is what it would get with any other values.
  - New `.ms_name_has_measurement_token()`: whole-token evidence only. It is a
    token from the measurement word list, or `.ms_name_has_sample_size_hint()`.
  - New `.ms_measurement_name_tokens()`: the word list, moved out of
    `.ms_name_has_measurement_hint()` so that both predicates read one copy.
    `.ms_name_has_measurement_hint()` behaves exactly as before.
- `tests/testthat/test-year-shaped-measurement-role.R` (new, 5 tests, 61
  expectations):
  1. Seven year-shaped measurement fixtures, covering double, character and
     integer storage and each kind of whole-word evidence (a measurement word,
     a sample size, a word followed by a unit), all type `measurement`.
  2. The invariant: moving the same values off the year range, with the same
     storage type, does not change the role. This includes an explicit factor,
     which stays `categorical`, and a method-named column, which stays

  3. With no measurement word in the name, the year shape still decides (`BY`,

  4. A substring or a unit in parentheses does not override the year shape

  5. End to end: `infer_dictionary()` then `suggest_semantics()` with an empty
     stub `search_fn`, so no network is used. The year-shaped column gets the
     measurement targets, identical to what the same column gets with values
     off the year range.

### Why whole words, and not the existing measurement hint

This design choice is settled by a measurement. The obvious fix is to let
`.ms_name_has_measurement_hint()` exempt a column from the year check. I tried
it against every CSV in the four local ecosystem checkouts before choosing:
metasalmon, metasalmonpy, smn-data-pkg and salmon-domain-ontology, 112 files and
1,271 columns, 35 of them year-shaped. It moves **18** columns, and **every one
is a rightly temporal `temporal_start` / `temporal_end`** in an SDP
`metadata/dataset.csv`, because the hint's substring pattern finds `temp` in
`temporal`. The unit pattern has a bare `g` alternative, so it accepts any
parenthetical containing a `g` (`Cohort (Aug)`, `Season (spring)`,
`Start (beginning)`). The whole-token rule moves **none** of the 1,271. So the
broad rule would only have regressed real columns, since the corpus contains no
year-shaped measurement column. The defect is latent, and the fix is aimed at
the data it would meet.

Residual, stated in NEWS: a name whose only measurement evidence is a substring
(`ADULTCOUNT`) or a unit in parentheses (`Mass (kg)`) still types `temporal`
when its values look like years.

## The mirror

Measured on metasalmonpy `main` `3f8349a` (Python 3.11.15, pandas 3.0.5),
using a `git archive` extract in the scratch directory. No metasalmonpy checkout
was touched.

- The defect is present. `spawner_count` as strings and `escapement` as int64
  both type `temporal`, and both type `measurement` off the year range.
- **Its year-shape predicate does not mirror R's for floats.**
  `_character_values()` renders through `str()`, and `str(1850.0)` is
  `"1850.0"`. So a float64 year-shaped column is never year-shaped there. The
  float64 `NATURAL_ADULT_SPAWNERS` types `measurement` by accident. A float64
  `BY` types `attribute` where R types it `temporal`. That case is reachable:
  `pd.read_csv` on `BY,n / 2001,1 / ,2 / 2003,3` gives float64 and `attribute`,
  while `readr::read_csv` on the same text gives numeric and `temporal`. With no
  missing cell pandas gives int64 and `temporal`.

The port is recorded as owed (parity port section and roadmap release index).
The float divergence is recorded there as something the port will meet: a port
that copies R's double fixtures fails its own year-shape control. It is not
absorbed, and it has no row.

  that such a change is safe.
- **Tests 3 and 4** pin right answers, not current wrong ones. They retire only
  if the year-shape heuristic itself is removed.
- No skip, suppression or allowlist was added.
