## What changed and where

One commit per defect, each with its test and its `NEWS.md` entry under the
development heading, then one commit for the queue and the cards.

1. **`DESCRIPTION`**: a `SystemRequirements` field names Python 3 and the
   `frictionless` Python package, and says they are optional and used only by
   `dwc_dp_build_descriptor(validate = TRUE)`. Test: `DESCRIPTION declares the
   Python toolchain that validate = TRUE runs` in
   `tests/testthat/test-dwc-dp-export.R`. It reads the field with
   `read.dcf(system.file("DESCRIPTION", package = "metasalmon"))`, as
   `test-knb-sdp-archive.R` already does.
2. **`R/semantics-helpers.R`**: when `llm_assess = TRUE`, `suggest_semantics()`
   passes `max_per_role` through `.ms_llm_effective_shortlist_size()`. That is
   the rule `.ms_llm_review_plan()` already applies for `create_sdp()`,
   `infer_dictionary()` and `infer_salmon_datapackage_artifacts()`, and applying
   it to a wrapper's widened value changes nothing. The widened value reaches
   both the first-pass retrieval and the LLM retry passes, as a wrapper's does.
   The roxygen text for `max_per_role` and `llm_top_n` says so, and
   `man/suggest_semantics.Rd` is regenerated from it. Only that file is
   regenerated: this machine's roxygen2 is 8.1.0, `DESCRIPTION` records 8.0.0,
   and 8.1.0 rewrote the layout of `NAMESPACE` and bumped the recorded version,
   so both of those were put back. Test file:
   `tests/testthat/test-llm-shortlist-width.R`, new, four tests.
3. **`R/term_search.R`**: the `mclapply()` results go through the new
   `.ms_checked_worker_results()`. It replaces each element a worker did not
   deliver with the record `run_source()` writes for a source that errored.
   That element is NULL when the worker died, and a `try-error` when an error
   escaped `run_source()`. The replacement has `status = "error"`, count 0, and
   the worker's own message, redacted, in `error`. So the existing
   degraded-lookup rules apply to it: `find_terms()` warns that the source did
   not answer and does not cache the result, and every caller of
   `.ms_search_failed_sources()` sees it. Tests: two, appended to
   `tests/testthat/test-term-search.R`.
4. **`R/ices-vocab.R`**: `.ices_text()` reads a missing column the way a
   missing value was already read, as `""`. `.ices_filter_text()` is now the one
   filter both find helpers use. `ices_codes()` keeps the rows of a response
   with no `key` column and gives them an `NA` detail `url`. Tests: three,
   appended to `tests/testthat/test-ices-vocab.R`. This was fixed rather than
   written up, although turning an error into a result can be a choice about
   behaviour. Here four things had already made that choice. The retirement
   condition names degrading as the behaviour wanted. The code's own `%||% ""`
   was written to degrade and never could. metasalmonpy already degrades, and
   its tests expect it to. And the error refused nothing on purpose: it was a
   data-mask crash. The one behaviour that gets quieter is the outage case,
   and it is recorded below as a candidate.
5. **Queue and cards**: `queue/items/B-300.yaml`, `B-301.yaml` and `B-302.yaml`
   are new. The #57 entry in `knowledge/backlog.md` now carries the
   re-measurement. The new mirror debt is recorded in both places the roadmap's
   rule asks for, in the same change: a passage in `knowledge/roadmap.md`'s
   release index, and one under *What metasalmon 0.5.0 owes the mirror* in
   `knowledge/parity-deviations.md`.

  directory, are decisions about the function's behaviour, not things the

## Found, not absorbed

- **Candidate, no item: no ICES helper can tell an outage from an empty
  answer, in either package.** `.safe_json()` signals a failed request and
  returns NULL, and `ices_code_types()` and `ices_codes()` turn that into the
  same empty tibble an unknown code type gets. Nothing warns. Before this
  branch the R find helpers aborted on it by accident. After it they return
  the empty result, as the list helpers always did and as metasalmonpy's find
  helpers do. `find_terms()` solved the same problem with its *did not answer*
  warning.
- **Candidate, no item: under `METASALMON_TERM_SEARCH_PARALLEL=false`, or on
  Windows, an error that escapes `run_source()`'s own handler still aborts
  `find_terms()`.** It is reachable only if that handler itself fails, and the
  forked path now records it instead, so the two paths differ for that case
  alone.
- **B-23** is the neighbouring shortlist defect in `infer_dictionary()`'s
  recursion, and was not touched.

## Guards added, and what retires them

- **`skip_on_os("windows")` on the two worker-failure tests** in
  `tests/testthat/test-term-search.R`. On Windows `find_terms()` searches
  serially, so the tests have no worker to exercise there. The retirement
  condition is written beside the tests: `find_terms()` forks on Windows too,
  or stops forking at all.
- **The `Sys.getpid()` check in the killed-worker test** refuses to kill the
  test process. If the search ever runs there, the fork was not taken, and the
  test fails on its worker-message assertion instead of passing vacuously. It
  retires with the test.
