## Where things stand

**Shipped in 0.2.0** — all nine P0 items from the comprehensive review. The
package is installable again, the schema contract is truthful, the SDP round trip
is lossless, published artifacts are byte-reproducible across machines, and
external text can no longer be evaluated as a cli template. Two static guards
(`test-cli-safety-guard.R`, `test-collation-guard.R`) keep the last two from
regressing, and both contracts are stated in `AGENTS.md` — which is now actually
tracked in git.

**Also fixed in 0.2.0, found in review of the release itself** — #64–#71. Every
defect automated review found on PR #11 was in code written *for* this release,
none in pre-existing code. The dominant shape was fixing one instance and
missing its neighbour (the same list, the same file, the same call path), and
the second was a safeguard tested only against inputs its author imagined. Both
are worth a deliberate pass on any future sweep of this size; see the entries in
`notes/bugs-and-improvements.md` for the specifics.

**Verified but not fixed** — the gcdfo validation layer (#44). All three claims
confirmed; the fix belongs in `dfo-salmon-ontology`.

**Baseline to hold at every step:** suite 0 failures, `R CMD check` Status OK,
Theme A replay PASS. A *rise* in the skip count is a regression — three 0.2.0
findings hid behind silent skips.

**The CI skip set is not the local skip set**, which is worth stating because
assuming otherwise is how the DataONE gap survived. Reading the actual CI log
rather than the local run is the only way to know what CI covers. As of 0.2.4:

| Category | CI skips | Status |
|---|---|---|
| Theme A integrity | 4 | Correct — they run in `theme-a-integrity.yaml` |
| Optional packages (`{dataone}`, `{datapack}`) | 5 → **0** | Fixed in 0.2.4 — installed, and absence now fails |
| Locale-differential guards | 3 → **0** | Fixed in 0.2.4 — runner generates the locales and runs under one |
| GitHub read helpers | 2 → **0** | Fixed in 0.2.4 — repointed from a private repo to metasalmon's own public one (#72) |
| **Total** | **9 → 4** | Every remaining skip is covered by another workflow |

**4 is the number to hold.** Any other skip in a check-workflow run is a
regression, and unlike a failure it will not announce itself.

Two of these deserve their own note.

*The locale group was the sharpest one.* Those three tests are the differential
guards on the byte-reproducibility contract built in 0.2.0 and 0.2.1 — and a
default runner has only C/POSIX collation, so they skipped and the contract's
own guards gave **no CI signal**. The static collation guard did run, so there
was defence in depth, but the differential half was inert.

Generating the locales was not sufficient on its own: R takes its collator from
the *startup* locale (ICU on Linux), so a later `Sys.setlocale("LC_COLLATE", …)`
did not change sort order and the tests still found no contrast. The workflow
now also sets `LANG`/`LC_ALL` to `en_US.UTF-8`, which has a second benefit worth
keeping: **CI is now the harder environment rather than the easier one.** Every
canonical-bytes path claims independence from locale, and the suite now runs
under a locale that actually collates differently. It passes — which is the
first real evidence for that claim rather than an assumption.

*The qualark pair looked like a stale org name and was not.* The repo genuinely
exists and is private, so CI's scoped token could not read it — the skip was
legitimate. But checking *why* it defaulted there surfaced the actual defect
(#72): `ms_setup_github()`, an exported function with nothing dataset-specific
about it, defaulted `repo` to that private repository, so any user calling it
with no arguments had a good token reported as broken. Both the function and
the tests now avoid it, and the tests read metasalmon's own public repository
instead — so the two skips became real coverage rather than being written off.

The lesson generalises: *a skip's stated reason can be accurate while the reason
it exists is a defect.* Reading the reason was not enough; asking why the
default pointed there was.

## Ranked next steps

Ranking is (does it bite a real user today) × (silent or loud) × (cost to fix).
Estimates assume one person working with the existing test suite.

### 1. Finish the reproducibility story — #43 · ~half a day — **DONE (0.2.1)**

Semantic ranking tiebreakers still break score ties on character keys, so a
seeded `column_dictionary.csv` differs between macOS and a C-locale container.
This is the **last locale-dependence in the package** and it lands in a
user-visible artifact. Deferred from 0.2.0 only because it moves existing
semantic-suggestion test expectations — do it as its own change so that diff is
readable. Add the affected functions to `collation_sensitive_fns`.

*Why first:* smallest item that closes a contract the rest of 0.2.0 already
claims, and it gets cheaper the sooner it happens (fewer seeded packages in the
wild to explain).

**Outcome:** done, together with #62 (the last hardcoded contract value), in
0.2.1. The stated cost — moving semantic-suggestion test expectations — did not
materialise: zero expectations changed, because the fixtures are lowercase ASCII
where C and the ambient locale agree, which is also why the bug was invisible.
**Next up is step 2.**

### 2. Make the semantic pipeline usable at real scale — #45, #46, #50 · ~1 week — **DONE (0.2.2)**

`.smn_term_index()` re-fetches and re-parses 11 Turtle modules on **every**
`find_terms()` call, and `METASALMON_CACHE` is read at build time so the result
cache can never be enabled in an installed package. Projected ~8 CPU-hours for a
5-table × 200-column package. Fold in #50 (HTTP failures reported as zero
results) because a degraded vocabulary service currently looks like an ontology
gap and drives spurious `request_new_term` escalation — wrong answers, not just
slow ones.

**Outcome:** done in 0.2.2. The root cause in both index builders was ordering,
not cache design — the stamp check sat after the fetch and the parse. Resolving
an index once per session also removes the fetch, at the deliberate cost of no
mid-session pickup without `refresh = TRUE`. #50 is handled by signalling rather
than throwing, because some `.safe_json()` calls are optional enrichment inside
a per-term map where an abort would discard the rows that did resolve; a
degraded lookup is additionally never cached. **Next up is step 3 or step 4 —
step 4 is the cheaper start, since #47/#51/#52 are each independently
shippable while step 3 needs `smn-data-pkg` coordination.**

*Gate:* a benchmark fixture asserting a **bounded number** of
`fetch_salmon_ontology()` and `search_fn()` invocations for a fixed target count.
Assert the call count, not wall-clock, so it is a real cache regression guard.

*Why second:* this is the difference between a demo and something that survives a
real package. It is also the largest single lever on user-perceived quality.

### 3. One validation authority — #48, #49 (with `smn-data-pkg`) · ~2 weeks

Three error-severity rules in `sdp.rules.yaml` are loaded and never executed, and
`validate_salmon_datapackage()` checks far less than it documents. metasalmon is
the workshop's designated final gate before DataONE deposit, so the gap is
load-bearing.

Sequence: give `smn-data-pkg` a LICENSE, CI, and Pages config; express the nine
prose-only rules machine-readably; declare the Frictionless target generation in
an ADR; then drive metasalmon's validator from the rule `id`s. **Add a
conformance test that fails when the spec declares a rule the implementation does
not execute** — that is the change that stops this recurring.

*Why third:* needs coordination across two repos, so it has the longest lead time
of the code work; start it once #2 is underway.

### 4. Publication ergonomics and provider robustness — #47, #51, #52 · ~3 days — **DONE (0.2.3)**

**Taken before step 3**, as this document suggested: each item is independently
shippable, while step 3 needs `smn-data-pkg` coordination.

**Outcome:** #47 turned out to be three gates rather than one — the archive
writer, the plan-mismatch check, and the resource-map ownership check all
treated an existing artifact as a published one — and was fixed by a single
principle: an artifact left by an *unpublished* dry run may be replaced when
`overwrite = TRUE`. #51's root cause was a default retry limit of 1 attempt,
which made the retryable-error classifier below it unreachable. **Step 3 is now
the only remaining P1 work.**

`publish_sdp_to_knb()` cannot re-plan after any edit (derived artifacts are
written with `overwrite = FALSE` and no override, and the abort message does not
say what to delete). Plus LLM retry/rate-limit handling and the BioPortal key in
the request URL.

*Why here:* each is small and independently shippable; #47 in particular is a
daily papercut for anyone actually publishing.

### 5. Correctness debt — #53, #54, #55, #56, #57 · ~1 week

The P2 cluster. #53 (4-digit measurement columns classified as `temporal`) and
#54 (literal `"NA"` code values destroyed on round trip) are the two that
silently lose user data; do those first.

*Gate:* extend the adversarial round-trip fixture from 0.2.0 with `"NA"`,
`"N/A"`, embedded newlines, and non-ASCII.

### 6. R-package and API hygiene — #58, #59, #60 · ~1 week, bundle into 0.3.0

Condition classes (#58) are technically breaking for anyone matching on message
text, so they want a major bump. Ship #59 and #60 alongside.

The cheapest item in the whole list lives here: **un-`\dontrun{}` the ~15 examples
that run offline in under a second.** It is an hour of work and it is the single
largest increase in what `R CMD check` actually validates.

### 7. Ecosystem — #61 · ~6 weeks, parallel track, mostly not R code

Highest strategic value, longest lead time, least code. Run this alongside
1–6 rather than after.

1. **Verify the 27 finder-only ontology findings.** Cheap and mechanical —
   `robot validate-profile --profile DL`, `pyshacl` against the *correct*
   namespace, run the competency SPARQL with rdflib. #44 already did three of
   them and all three held, so expect a high confirmation rate. Do this before
   anything else here.
2. **Fix #44** so the gcdfo quality gates stop being placebos — and note the
   repo's `venv/bin/python3.14` is a dangling symlink, so `make` targets that
   shell into it fail before they start.
3. **Make vocabulary-release pinning possible**: monotonic versions, real
   `owl:versionIRI` in every serialization, restored `0.0.8`, immutable release
   snapshots. Then thread the resolved release into metasalmon's output and the
   KNB transformation record. **metasalmon's own KNB documentation states this as
   a precondition and it cannot be satisfied today.**
4. **Publish the `smn:`/`gcdfo:` boundary as data** — one SSSOM 1.1 mapping set
   for the ~55 name collisions, with a CI check in both repos. Then make
   metasalmon's namespace routing read it instead of inferring it.
5. **Populate the three empty policy schemes** (PA zones, COSEWIC, benchmarks).
   Highest-value single ontology change for actual users: today term search finds
   nothing and falls back to `REVIEW:` placeholders.
6. **Fix the I-ADOPT layer** so the decomposition pipeline has a conformant target.
7. **Governance**: machine-readable CC BY 4.0 in the TTL, real `CITATION.cff` per
   repo, named editorial authority and review SLA, org-owned URLs replacing
   personal-account ones, one accurate `entrypoints.md` per repo.

### Continuous

- **Workshop.** Convert the episodes to real knitr chunks pinned to a released
  metasalmon, add the lockfile entry, write the six missing solutions, teach SKOS
  mapping properties and SSSOM, make the LLM section runnable with its failure
  modes. Once episodes execute, the workshop becomes an integration test of the
  public API — which is where stale-call bugs get caught for free.
- **Keep the guards honest.** Any new byte-producing function goes in
  `collation_sensitive_fns`; any new cli call uses literals or the escaping
  helpers. Both are stated in `AGENTS.md`.

## Two process notes worth keeping

**A green suite was not the signal it looked like.** Three 0.2.0 findings were
invisible to 21k lines of tests because the suite pins
`sdp_schema_source = "vendored"`, never round-trips a package through its own
validator, and skips network-gated tests silently. One existing test was passing
*because of* a bug. The two cheapest structural improvements are already in
0.2.0 (the adversarial round-trip fixture and a live remote-schema test); the
third — **asserting that optional-dependency tests do not skip in CI** — landed
in 0.2.4.

That third one paid immediately and confirmed the worry was not theoretical:
`R-CMD-check.yaml` installed only `devtools` and `rcmdcheck`, so five tests of
the **DataONE adapter boundary** — the code that talks to the repository during
live publication — had skipped on every machine, including CI, and had never
executed once. They pass. Nobody could have known that. CI now installs the
packages and fails if any is missing, and a check-workflow run should report
exactly four skips (the Theme A integrity tests, which run in their own
workflow).

**Two "fixed" markers in the backlog were wrong** (#9 and #33), both fixed in
ways nobody could verify from a clean clone. Items #34+ now name the check that
proves them. Prefer claims CI can assert.
